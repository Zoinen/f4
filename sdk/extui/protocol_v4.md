# ExtUI semantic protocol v4

ExtUI v4 keeps the existing four-byte big-endian length prefix and MessagePack
encoding. Semantic state is never sent as an unversioned top-level map. Every
semantic message uses this envelope:

```text
type          "extui"
version       4
sequence      non-zero connection-wide sequence
streamId      stable stream identity
revision      non-zero revision within streamId
baseRevision  previous stream revision; absent only for snapshot
kind          snapshot | patch | reset | append | metadata | rows | intent
payload       kind-specific typed payload
```

The canonical streams are `chrome`, `workspaces`, `shell`, `menus`, `dialogs`,
`command-line`, `operations`, `panel/<side>`, and `document/<stable-id>`.
Panel catalog rows and document text rows only occur in their corresponding
panel/document stream. A revision gap requests a snapshot for that `streamId`
alone.

Control messages (`hello`, `palette`, fallback `frame`, `cursor`, clipboard,
platform transport, and `quit`) are transport-level and intentionally do not
use semantic revisions.

The canonical cross-language examples are generated by Go into
`testdata/v4_envelopes.msgpack` (`go generate ./sdk/extui`). Qt decodes that
exact binary in `ExtUiProtocolTests`; changes to envelope names, integer
representation, stream identity, or nested typed payloads therefore require a
coordinated Go/Qt update.

## Standalone document geometry and coherent windows

The `documentViewportV1` hello capability enables Qt-owned standalone viewer
and editor geometry. Qt reports the prospective body even while panels are
visible, using a session-scoped action:

```json
{"target":"app","action":"document.viewport","scope":"standalone","columns":97,"rows":28,"geometryRevision":3}
```

The session retains the newest positive geometry revision across document
closure. Older clients and console presentation retain console-derived sizes.
Before the first measurement, a capable session receives pending metadata, not
text wrapped to a guessed console width. Geometry does not resize hidden PTYs.

Document surfaces include `viewportColumns`, `viewportRows`,
`geometryRevision`, `layoutRevision`, `layoutPending`, and `loadError`.
`layoutRevision` identifies the source-to-cell mapping; width, wrapping, tab
stops, and source edits can invalidate it. Reflow preserves a source-byte
anchor. A ready window atomically supplies its rows, extents, layout identity,
viewport placement, and acknowledged `windowGeneration`. An incomplete index
has `contentExtentKnown:false`; placeholder rows are not an extent.

Scroll actions carry a monotonic `generation` and the displayed
`layoutRevision`. The core retains newest intent without acknowledging it until
the visible rows are ready. The frontend rejects superseded generations and
keeps the last coherent same-document window while waiting. A different
document never inherits those rows. A permanent `loadError` ends the wait
without pretending incomplete bytes were presented.
`windowRequestGeneration` identifies the demand producing an error without
acknowledging an unsatisfied window; an obsolete error cannot cancel newer intent.

Native `editor.mouse` actions identify the displayed `documentKey`,
`layoutRevision`, source fragment `rowOffset`, fragment-relative `column`, and
displayed `scrollLeft`. They are not clamped through console coordinates.
Reflow invalidates active gestures; even a stale release clears capture.
Cursor/status and regular stream-selection changes do not publish or reproject
row models. A compact editor state contains the complete cursor and selection
state, including `cursorAbsoluteRow`, `cursorAbsoluteColumn`, `selection`,
`selectionAnchorRow`, `selectionAnchorColumn`, and the selected foreground,
background, bold, underline, and strikeout values. It also carries the current
`documentKey`, `layoutRevision`, and `windowGeneration` as identity fences.
Native clients atomically replace the previous compact state; consequently an
inactive selection is sent explicitly as `selection:false`, never inferred from
an omitted field. A mismatched fence cannot alter the visible caret, selection,
or row window. Regular selection is painted as a clipped overlay over immutable
base rows; rectangular and specialized editor modes retain row-based styling.

The transport-level `focus` message carries a boolean `focused` for actual
application activation, independently of internal frame/control focus.
