# Issue #420 — статус проверки

Дата проверки: 08-09-2026.

## Итог

В текущем `main` отдельный production-срез для #420 не требуется: оба
первоначальных наблюдения и последующий вопрос о символе/цвете уже покрыты
слитым PR #564 (`f3a5e23b5bb8fae4df9cdbe28dc3d6d7c42aca2f`). Тикет оставлен
открытым; закрыть его может только пользователь после своей проверки.

## Что проверено

- Для строки под курсором атрибуты берутся через `vfs.Lstat`, поэтому диалог
  описывает саму символическую ссылку, а не конечный объект.
- В диалоге сохраняется `Target`, то есть направление ссылки.
- Встроенные стили `classic`, `default_dark`, `modern` и `radiola` содержат
  отдельное правило `Symbolic Links` с `IncludeAttributes = Symlink`.
- Пользовательский цвет и маркер настраиваются тем же механизмом правил
  подсветки; отдельный специальный формат настроек для ссылок не нужен.
- В PR #564 есть регрессионные проверки для `Lstat`, атрибутов ссылки и всех
  встроенных стилей. GitHub Actions PR #564 завершились успешно, включая
  Linux/Windows/несколько BSD и Darwin-профилей.

## Решения и инварианты

- Диалог атрибутов и подсветка должны описывать одну и ту же запись под
  курсором; переход к `Stat` допустим только как fallback для VFS без понятия
  символических ссылок.
- Маркер ссылки не дублируется правилом подсветки: встроенная стрелка панели
  остаётся видимой независимо от `ShowHighlightMarks`, а цвет берётся из
  обычного правила `Symlink`.
- Новая реализация не должна закрывать тикет автоматически.

## Проверка пользователем

1. Создайте символическую ссылку на Linux или другой поддерживаемой системе и
   откройте каталог в f4.
2. Убедитесь, что ссылка отличается от обычного файла/каталога по маркеру или
   цвету.
3. Поставьте курсор на ссылку и откройте `Ctrl+A`: сведения должны относиться
   к самой ссылке, а поле `Target` — показывать объект назначения.
4. При необходимости измените правило `Symlink` в настройках подсветки и
   убедитесь, что цвет/маркер меняются без отдельной настройки панели.

Локальные сборки и тесты не запускались согласно инструкции проекта; выше
зафиксированы результаты GitHub CI связанного PR.
