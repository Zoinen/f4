# Share the detected base font size with GUI monospace defaults

**Date:** 2026-10-11 13:00
**Files:** qt/host/qml/HostTypography.qml, qt/host/qml/F4HostWindow.qml,
qt/host/src/main.cpp, qt/host/tests/F4QuickViewSurfaceTests.cpp,
qt/host/CMakeLists.txt, qt/host/README.md
**Severity:** low

## Problem

Default and Reset monospace sizes were independent of the detected regular
base size. The window could also choose the legacy launcher size instead.

## Root Cause

The shared typography model used a numeric monospace default, while the host
selected a separate FixedFont/launcher size. Reset persisted the current size
as a number instead of retaining the default sentinel.

## Solution

Use the detected base UI size for both monospace default and Reset, retaining
the separate fixed-pitch family. Reset restores the zero-size sentinel, so
saved defaults follow subsequent platform changes. Explicit GUI sizes remain
independent. macOS publishes one GeneralFont pixel-size measurement for both
roles and exposes an opt-in VTUI_DEBUG diagnostic.

## Prevention

The regressions first failed at 16 vs 12 px in HostTypography and 17 vs 15 px
in the actual host window. Coverage now checks system-size changes, custom
size/family preservation, Reset, default persistence, and actual text leaves'
origins/extents and unit transforms at DPR 1.75. Keep them in the native font
CTest gate rather than relying only on the full UI suite.

Canonical CGO_ENABLED=0 Go and video/FFmpeg Qt builds pass. Six related CTest
suites pass, including document rendering and native settings. In the rebuilt
live app, both Reset tooltips show 13 px; changing monospace to 36 px then
Reset returns it to 13 px. Cancel restores the user's saved preferences.
