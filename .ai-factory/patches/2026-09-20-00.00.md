# Native Linux QML font policy

Date: 2026-09-20

## Summary

Made the Qt/QML frontend use the desktop's native proportional font for
application chrome while retaining the desktop's native fixed-width font for
terminal and document content. On the current KDE Wayland system the resolved
families are `Noto Sans` and `Noto Sans Mono`.

## Root cause

`F4HostWindow.qml` used `Monaco` as the fallback for every QML text role. The
font is not installed on this Linux system, and UI chrome and fixed-width
content were not modeled as separate roles.

The portable host exposed a second Linux-only problem: its statically linked
Fontconfig library retained the Conan build prefix as its default configuration
location. After extraction, that path does not exist, so Qt reported a missing
Fontconfig configuration and could resolve only the generic `Sans Serif` and
`monospace` requests.

## Changes

- Initialize portable Linux Fontconfig from `/etc/fonts/fonts.conf` before
  constructing `QGuiApplication`, while preserving caller-supplied Fontconfig
  configuration.
- Resolve and expose distinct system UI and fixed-width families from the Qt
  host. An explicit configured GUI family remains the override for both roles.
- Route application chrome, search, key-bar, queue, and theme-editor text to
  the UI role.
- Keep the terminal grid, command line, help/document bodies, and other
  column-sensitive content on the fixed-width role.
- Correct the Fast Find text's settled scene transform after the changed font
  exposed a fractional physical-pixel origin at 175% scale.
- Add gated `[FIX:native-font-policy]` startup diagnostics.

## Regression evidence

Before the QML role implementation, the new test failed with:

```text
Actual   uiFontFamily: "Sans Serif"
Expected uiFontFamily: "F4 Platform UI Test"
```

The first 175% run after role separation also measured the Fast Find text at
the fractional physical origin `(390.5, 973.75)`. The scene-space correction
returns both UI and fixed-width leaves to whole physical pixels and preserves
unit transforms.

The following targeted tests pass:

```text
F4NativeFontPolicyPixelGridTest
functionBarSameCountUpdatesPreserveDelegates
functionBarLeavesStaySharpAndThemeLiveAt175Percent
pathBreadcrumbTextStaysFixedWhenNavigatingDeeper
themeDialogControlsStayOnPhysicalPixelGridAt175Percent
```

The native-font regression also grabs and validates rendered UI and fixed text
at `QT_SCALE_FACTOR=1.75`.

## Build and live verification

- The Ubuntu 18.04 arm64 Qt host passes the glibc 2.27, PIE, RELRO, BIND_NOW,
  and non-executable-stack portable audit.
- The embedded Go launcher passes its static ELF audit with no interpreter or
  `DT_NEEDED` entries.
- The packaged Qt frontend is running directly with `--gui=qt`.
- Runtime diagnostics report `ui=Noto Sans`, `fixed=Noto Sans Mono`, and QWK.
- Qt RHI selected hardware OpenGL through Mesa on `Apple M2 (G14G B0)` with
  `Prefer software device: 0` under the Wayland session.
- A final active-window capture was inspected for correct layout and rendering.

## Unrelated baseline

The repository-wide portable CTest invocation still contains pre-existing
failures outside this change: architecture-size/pragma violations, tests that
write diagnostics to Windows or missing directories, mixed-DPR test groups,
and existing menu/gallery/controller expectations. The focused font, pixel
grid, embedded-payload, host smoke, and portability gates above pass.

## Prevention

Keep QML text assigned to an explicit semantic font role and retain the 175%
scene-coordinate plus rendered-image gate whenever either role or its layout
changes. Portable Linux startup must initialize Fontconfig before any Qt GUI
object is created.
