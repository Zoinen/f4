# Panel navigation toggle, native command caret, and Details zoom

**Date:** 2026-09-22 18:00
**Files:** internal/panel/navigation.go, internal/app/actions_table.go, internal/keymap/{farkeys,hotkeys}.go, internal/cmdline/{line,qt_semantic}.go, internal/panel/{frame,qt_semantic}.go, third_party/vtui/{edit,edit_multiline,semantic}.go, qt/host/qml/CommandLineView.qml, third_party/ZoinGallery/qml/{GalleryEntryDelegateBase,GalleryEntryPreview,DetailsEntryDelegate}.qml, related regression tests and documentation
**Severity:** medium

## Problem

Panel navigation lacked a reassignable Search-first/Classic toggle. GUI command
input clicks only focused it; vertical arrows selected history instead of moving
within multiline input. Details rows grew with zoom but their preview slots did
not, and names remained single-line.

## Root Cause

- Native pointer offsets were not routed to the authoritative Go editor.
- History dispatch did not distinguish visual-line navigation from boundary
  navigation. Qt display offsets also include synthetic argument line breaks.
- Rebuilding rich-text presentation on semantic cursor updates reset preferred
  columns; changing document format independently could expose serialized HTML.
- Native cursor clamping reused terminal clusters, which omit newline characters.
  Live diagnostics proved Qt sent offsets 5 and 3 while Go clamped them to 4 and 2.
- Details layout and preview geometry used independent sizes.

## Solution

Register Panel.ToggleNavigationMode with Ctrl+grave and Ctrl+Shift+grave, including
physical macOS Control, command search, remapping and checked Options state.
Use semantic cursor/history actions, UTF-16-to-rune conversion and source/display
offset mapping. Preserve a preferred visual column, use history only at the
outer visual-line boundaries, and retain the existing authoritative Go text.
Apply rich-text format, text and semantic cursor together; reset preferred columns
only when source text changes. Preserve valid multiline newline boundaries when
clamping native cursor positions. Debug logging records offsets, not input text.

Share the zoom-dependent Details preview rectangle between image and icon leaves.
Derive filename line count from available height; use wrapping plus trailing
ellipsis for multiline text and retain compact middle elision.

## Prevention

- Reproduce before implementation: pointer and arrow tests failed before fixes;
  Details tests failed on fixed preview size and fractional physical origins.
- Test frontend semantic actions and backend cursor application together: isolated
  Qt arrow tests passed while backend newline clamping still broke live insertion.
- Test literal newlines, empty lines, graphemes, synthetic breaks, soft wrapping,
  rich/plain presentation changes, and preferred-column restoration.
- Do not suppress repeated keyboard events to hide ordering bugs.
- Inspect actual preview/icon/text leaves and their transforms at DPR 1.75.
  Qt input tests passed (12 cases including setup/cleanup); gallery tests passed
  (7 including setup/cleanup). Focused Go app/keymap/panel/cmdline and vtui tests
  passed. Both Go and Qt host builds succeeded.
- Live macOS verification covered toggle, pointer insertion, Up/Down insertion,
  Details zoom, multiline wrapping and truncation. Restored panel widths, zoom,
  Search-first mode and cleared test input afterward.
- Existing commandLineClickTransfersFocus panel-focus assertion also fails with
  original HEAD CommandLineView.qml; this is a separate baseline failure.
- Additional useful coverage: real input-method composition and non-US keyboard
  layouts through the complete native host, beyond key-normalization unit tests.
