# Retain source-space video conversion throughout panning

**Date:** 2026-10-07 13:26 Europe/Moscow
**Files:** `third_party/ZoinGallery/qml/ViewerResample.qml`,
`third_party/ZoinGallery/ViewerLinearVideoTexture.cpp`,
`third_party/ZoinGallery/tests/ViewerResampleGpuTest.cpp`
**Severity:** high

## Problem

Dragging the video surface during playback slowed both F4 and the desktop
compositor, despite stationary playback using the optimized path. A fresh
six-second baseline on Apple M2 Wayland/OpenGL accepted 180 video frames but
filtered only 111 distinct revisions (about 19 fps). GPU scheduler completion
p95 was 61.718 ms for Qt and 56.817 ms for KWin. There were zero conversion
submissions; all 150 final filters used direct video-plane sampling.

## Root Cause

Source-sized RGBA32F conversion eligibility was coupled to
`presentationCacheEligible`. That predicate intentionally rejects motion,
fractional scene placement, opacity and non-unit ancestor transforms so a
finished, quantized presentation is never incorrectly reused. Applying the
same predicate to source-data conversion destroyed useful reuse during drag
and restored repeated YUV-to-linear-light conversion inside every filter tap.

The conversion pass has an independent matrix and opacity 1, and does not
include presentation filtering or dithering. Its dependencies are source
identity, frame revision, source geometry/metadata and RHI, not scene pan.

## Solution

- Separate conversion eligibility from final presentation eligibility. Require
  a valid video frame and finite positive viewport dimensions explicitly.
- Preserve source extent/pixel-budget bounds, direct-minification threshold,
  native/nearest and pyramid exclusions, reference mode, RHI capability and
  aggregate-memory admission, failure latching and original-quality fallback.
- Leave filter kernels, transfer functions, taps, dithering, continuous motion
  coordinates and resting pixel-grid behavior unchanged.
- Keep the converter Loader/provider alive through drag/rest layer toggles.
  The existing revision key now avoids converting an unchanged panned frame.
- Add opt-in `F4_VIEWER_LINEAR_CONVERSION` submission diagnostics under
  `F4_VIEWER_RESAMPLE_DRAW_TRACE`; normal playback logging remains unchanged.

The pre-fix hardware regression fails in `work/video-pan-before.txt`. Eight
expanded rows cover BGRA/NV12, DPR 1/1.75 and the real viewer hierarchy. Every
rendered pixel matches the original reference with tolerance zero through
fractional/clipped pans, unchanged redraw, frame replacement, inherited fade
and transform, release and settled reuse. Tests verify provider identity,
actual RGBA32F selection, exactly one conversion per new frame, zero repeat
conversions, and actual resting scene origins/extents/unit transforms.

Live post-fix dragging records 180 conversions for 180 incoming frames and
360 moving filters in six seconds (full 30 fps video and 60 Hz pan redraws),
with no converter construction/destruction. Qt completion p95 is 11.774 ms,
KWin 3.249 ms. Paused dragging records 360 filters of the same revision and
zero conversions; settled idle records zero filters/conversions. These are
GPU scheduler completion latencies including contention, not isolated GPU
execution time or utilization.

The broad GPU suite has 232 passes and the same four pre-existing image-only
failures; real decoded video has five passes, CPU resampling 27, embedded QML
imports three. No existing quality assertion was relaxed. Portable native ABI/
hardening, embedded-host extraction and static Go audits pass. Qt/FFmpeg were
reused, not rebuilt; the native host was embedded into the canonical Go binary.

Normal-profile restoration separately triggered a Fishplus typed-nil file
close panic in Go. No unrelated fix was applied. The rebuilt Qt application is
left open and paused using a temporary local-only profile, with saved remote
workspaces retained. The incomplete audio plan remains intact. No commit/push.

## Prevention

- Define each cache by its own dependencies, not another cache's eligibility.
- Benchmark actual pointer dragging, not only stationary or paused redraws.
- Count conversion and filter submissions independently, including repeated
  source revisions and allocation churn. Verify source conversion is reused
  while the final continuous presentation is regenerated.
- Require exact pixels and full scene transforms at fractional DPR when
  admitting a source-space cache in formerly excluded presentation states.
- Further useful coverage: equivalent drag/release regressions on Windows
  D3D and macOS Metal, device-loss/multiple-viewer admission stress, and a
  separate regression-first fix for the remote typed-nil close failure.
