# Publish embedded-probe geometry to the catalog

**Date:** 2026-11-25 00:17
**Files:** third_party/ZoinGallery/src/embed/ExternalCatalogDecode.cpp, third_party/ZoinGallery/tests/GallerySessionTest.cpp
**Severity:** medium

## Problem

A JPEG uploaded to iPhone and several adjacent PNG thumbnails stayed blank, even after restarting F4. Remote reads and thumbnail decodes succeeded.

## Root Cause

The bounded embedded-image probe populated only the lazy ImageFile facade. Catalog originalSize and imageInfo remained unknown. Masonry uses catalog geometry and a complete-row metadata barrier; the unresolved JPEG therefore prevented the first row from becoming visible despite successfully published pixels.

## Solution

Publish orientation-correct dimensions and imageInfo into the catalog before notifying ImageFullSizeRole, KnownImageSizeRole and VisualSnapshotRole. Leave full metadata completion unchanged. Add an opt-in media timing event for the geometry publication.

## Prevention

- Regression test delivers a successful remote probe while full metadata work is blocked, then asserts catalog and visual snapshot dimensions, including orientation.
- Confirmed the test fails before the fix (QSize(-1,-1)), then passes at 175% scale along with remote progressive decoding and viewer probe-barrier tests.
- Rebuilt and launched the canonical Qt host; visually verified the uploaded JPEG and previously blank adjacent photos now display.
- Broader future coverage could combine delayed probe geometry with a rendered multi-image Masonry row.
