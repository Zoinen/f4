# Reserve Alt shortcuts for file-panel sizing

**Date:** 2026-09-17 23:35
**Files:** qt/host/qml/GalleryPanelInputRouter.qml; third_party/ZoinGallery/qml/GalleryPanelInput.qml; qt/host/tests/F4GalleryBridgeTests.cpp; qt/host/README.md
**Severity:** medium

## Problem

Panel sizing intercepted Plus/Minus and Ctrl combinations needed by F4.
The requested replacement is Alt+Plus/Minus, for file panels only.

## Root Cause

The host router owned Ctrl/Meta zoom shortcuts, while the embedded Gallery
panel independently consumed unmodified operators before they reached its
parent router. Changing the parent modifier test alone left that conflict.

## Solution

Reserve Alt+Plus/Equal, Alt+Minus and Alt+0 for sizing/reset in the host.
Allow Shift when typing Plus and ignore the keypad marker. Ctrl/Meta
combinations, including Ctrl+Alt, keep their commander routing.
An optional galleryOwnsZoomShortcuts capability lets the embedder disable
Gallery's built-in operator shortcuts; its default behavior is preserved.
Record accepted shortcuts under the existing opt-in navigation trace with
the [FIX:panel-alt-zoom] marker. Viewer bindings are unchanged.

## Prevention

Test both key-down and key-up through the actual embedded panel, with each
operator starting outside pending command-line input. Otherwise the prior
text-input latch can hide a consumed shortcut. The regression first failed
because Alt+Equal left height at 150; after the router change it exposed a
plain operator delivering zero presses and one release. Both now pass.

The integration check covers Masonry and Details sizing, reset, shifted Plus,
keypad keys, plain/Ctrl/Meta operators and Ctrl+Alt forwarding at DPR 1.75.
GalleryQmlInteractionTest, static QML imports, compiled-host QML loading,
Windows DLL audit and embedded payload/extraction checks also pass.
No static layout or viewer key bindings were changed.
