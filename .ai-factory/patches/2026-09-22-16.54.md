# Long local shell commands never reach execution

**Date:** 2026-09-22 16:54
**Files:** internal/panel/frame.go, internal/panel/frame_command.go, internal/panel/frame_command_test.go, internal/panel/frame_command_darwin_test.go, docs/TERMINAL.md
**Severity:** high

## Problem

A repeated 1031-byte image-generation command wedged the Qt terminal. The UI
accepted input, but the generator never started and subsequent commands did not
execute normally.

## Root Cause

The local shell handoff assumed that a successful PTY write meant an arbitrarily
long interactive command arrived intact. The 1176-byte wrapped line was logged
intact before and after Write, but captured zsh input changed at byte 1024: its
tail was replaced with earlier text, including loss of the terminating CR.
The shell never emitted C; f4 had already prepared/muted the command and marked
execution active. The precise low-level source of byte substitution was not
established. Smaller Write calls also failed the real-PTY regression, so pacing
or chunking was not accepted as the solution.

## Solution

Keep short commands inline. For long/multiline local foreground commands, stage
a quoted eval invocation in the existing private shell-runtime session and send
a bounded read/eval expression inside the unchanged outer C/D wrapper. Do not
source a script or start another shell: parent-shell state and $0 remain intact.
Keep the payload until execution completion and remove it on failure, shell
replacement, or frame close. Existing shutdown/stale-session cleanup handles a
crashed owner. Log payload lengths, never contents.

## Verification

- `TestLocalCommandLongInteractiveRoundTrip` failed before the fix with no full
  command output, and passes afterward (20 commands per run, five repeated runs).
- Staged/direct eval parity passed for sh, bash, and zsh: quoting/Unicode,
  persistent state, aliases, stdin, syntax errors, trailing newline, and status.
- Private permissions, creation errors, missing-file completion, lifecycle
  cleanup, failed writes, and short writes pass.
- Full `internal/terminal` suite and focused panel/application shell suites pass.
- Full panel suite retains its known unrelated
  `TestSameDirectoryRefreshKeepsCatalogDuringReadAndNoOpRevision` failure.
- Fresh worktree Go binary and Qt host built. The exact user command generated
  three new JPGs in the actual Qt app, completing in 6.79, 6.47, and 7.45 seconds.
- A staged `sleep 60` was interrupted with Ctrl+C; the next exact generation
  command succeeded. No command payload files remained afterward.

## Prevention

Test repeated long input against a real interactive PTY, including immediately
after a prior command completes. A successful write count is not a shell-level
acceptance acknowledgement. Keep execution markers outside user syntax and
outside fallible payload reads. Assert cleanup on all terminal lifecycle exits.
Broader future coverage: deferred environment-update delivery failures and
remote-shell long-input transport need their own regression fixtures.
