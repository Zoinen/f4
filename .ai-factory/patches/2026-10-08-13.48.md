# Verify Conan remote revisions independently of local settings

**Date:** 2026-10-08 16:48 MSK
**Files:** `ci/upload-conan-packages.py`, `ci/test_portable_conan_upload.py`
**Severity:** medium

## Problem

After the local-cache check was corrected, the AMD64 release build still failed
while verifying an exact Qt package revision on Artifactory. Conan's upload
step reported that the same recipe and package revisions were already present.

## Root Cause

The expected remote package set was already selected by architecture from the
local cache, but remote verification repeated the architecture filter against
the remote listing. Remote results need not include the local package
`info.settings` metadata, so an existing exact package revision could be
reported as missing.

## Solution

Keep architecture filtering on the local cache. Verify that Artifactory
contains each exact recipe revision, package ID, and package revision selected
locally, without requiring architecture metadata from the remote listing. Add
a regression where the remote exposes revisions but omits local settings.

## Prevention

- Apply platform/configuration filters where configuration metadata is
  available, then verify exact immutable package references on the remote.
- Test both local and remote JSON shapes; they do not necessarily expose the
  same package metadata.
