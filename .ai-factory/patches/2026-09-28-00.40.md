# Preserve automatic column sizing through full scene projection

## Problem

Navigating into or out of a folder changed the size-column width in the opposite,
unchanged panel.

## Root cause

The typed incremental scene retained `PanelColumnModel.AutoWidth`, but the legacy
map-to-model conversion used for full scenes omitted it. Navigation alternated
between full and incremental scenes, so both panels temporarily switched between
automatic font-based sizing and legacy relative sizing. This also produced an
unnecessary column-schema delta for the opposite panel.

## Fix

Copy `autoWidth` in `appPanelFromLegacy` alongside the other column properties.
Missing values remain false for compatibility with older scene producers. No
additional cache or QML sizing workaround is needed.

## Regression coverage

- Round-trip automatic and manual name, size, and metadata columns through the
  full-scene projection, including legacy columns without `autoWidth`.
- Simulate child/parent/child navigation in either panel across full and
  incremental scenes. Reject column-schema deltas and updates to the opposite
  panel when its content and schema have not changed.
- Both new tests failed before the fix and passed afterward.
- `CGO_ENABLED=0 go test ./internal/nativeui ./sdk/extui` passed.
- Canonical worktree Go and Qt builds passed.
- Related Qt font-sizing, panel-update, renderer-lifetime, and gallery column
  geometry tests passed, including DPR 1.75 checks.
- Restarted the worktree application and verified repeated folder navigation in
  both panels without opposite-panel size-column movement.

## Prevention

When adding semantic model fields, audit full-scene adapters as well as typed
incremental paths. Cover equivalence across these paths so rendering policy does
not change merely because the transport chooses a full snapshot.
