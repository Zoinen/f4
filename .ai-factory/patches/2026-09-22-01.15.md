# Fix: grouped gallery pointer routing

## Problem

After enabling Group by in the Qt gallery, the shared pointer layer remained
above the materialized gallery delegates. Group headers are children of the
native layout, so their QML `MouseArea` could not receive hover or click
events. The failure was most visible after the first ungrouped parent entry:
grouped content appeared non-interactive.

## Root cause

`GalleryPointerLayer` is intentionally the single analytical hit-test owner
for recycled file delegates. The grouped header layer was rendered below that
root-level pointer sibling and had no equivalent route for header hit testing.
The existing native file-index lookup did not identify section headers.

## Fix

- Added bounded `groupHeaderKeyAtPointer()` resolution in
  `GalleryViewport.qml`, using the visible native header model and the
  existing sticky/column geometry.
- Routed primary presses that land on a header through the shared pointer
  layer to `toggleGalleryGroup()` and retained the existing analytical file
  hit-test path for catalog entries.
- Derived the sticky push-off position from the immediate next ordered header,
  keeping pointer lookup O(H) rather than scanning the visible header list for
  every candidate.
- Added pointer-hover highlighting/tooltips through the panel's published
  hover coordinates, so visual feedback remains correct even when the shared
  pointer layer owns the event.
- Added opt-in `[FIX:grouped-pointer-routing]` benchmark trace metadata.

## Regression coverage

- Host-level transition from an already-live ungrouped panel to grouped state:
  grouped row hover/click, header hover/click, collapse state, and no pointer
  leakage to the embedding surface.
- Gallery-level grouped item mouse interaction regression.
- Existing selection-modifier mouse regression.
