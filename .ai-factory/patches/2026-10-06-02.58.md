# macOS crash during concurrent gallery natural sorting

**Date:** 2026-10-06 02:58
**Files:** `third_party/ZoinGallery/NaturalSort.h`, `third_party/ZoinGallery/GalleryViewModel.h`, `third_party/ZoinGallery/GalleryViewModel.cpp`, `third_party/ZoinGallery/tests/GallerySessionTest.cpp`
**Severity:** high

## Problem

The Qt host aborted while background folder-preview tasks selected and naturally sorted images. A concurrent stress test reproduced an Apple allocator/ICU crash inside `QCollator` initialization.

## Root Cause

Each worker created or copied a `QCollator` while other workers did the same. On this macOS runtime, concurrent ICU collator initialization corrupted locale/cache state. Copying a supposedly shared collator still initialized a separate ICU collator and remained unsafe.

## Solution

Create one `QCollator` per thread and serialize only its first initialization. Comparisons then use the thread-local collator without a global lock. Route `GalleryViewModel` natural comparisons through the same helper. Add a 16-thread regression test that performs repeated folder-preview natural sorts.

## Prevention

- Keep locale-backed collator construction out of concurrent first-use paths unless initialization is synchronized.
- Keep one collator per worker thread instead of copying a shared template.
- Retain a parallel regression test for folder-preview sorting on macOS.
