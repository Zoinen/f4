# Android USB discovery and authorization recovery

## Symptom

An Android phone was physically connected over USB, but the Android drive in
the running Qt app was empty. The local ADB daemon was alive, yet its device
snapshot contained only emulator transports.

## Evidence

- macOS IORegistry reported a USB `vivo X200 Ultra` with serial
  `10AF4E11EP002LE`.
- Before recovery, `adb devices -l` returned only `emulator-5554`.
- A manual `adb kill-server` followed by `adb start-server` returned the phone
  as `10AF4E11EP002LE device usb:0-1.1.1`.
- The running f4 instance then listed `V2454A (10AF4E11EP002LE)` alongside the
  two emulators and opened the Android root successfully.

## Root cause

The Android source treated a successful `host:devices-l` response as complete
even when it had no USB transport. It therefore did not rebuild an ADB daemon
that had missed a hot-plugged phone. In addition, executable discovery did not
include the standard macOS SDK location, so a recovery restart could not find
`adb` when it was not on `PATH`.

## Change

- Parse the `usb:` property from ADB long device records and carry it through
  the Android device model.
- On discovery snapshots without a USB transport, perform one serialized,
  cooldown-bounded ADB daemon refresh and query the devices again.
- Add a visible `Refresh device list` action for an explicit retry when the
  current snapshot still has no USB transport.
- Keep unauthorized USB transports visible; opening one uses the existing
  restart-and-poll authorization flow.
- Search standard per-user Android SDK locations on macOS, Unix, and Windows
  in addition to the existing override/environment/PATH locations.
- Add `[FIX:android-discovery]` diagnostics for initial, refreshed, and failed
  discovery attempts without logging credentials.

## Regression coverage

- `TestServerDeviceSourceRefreshesStaleUSBSnapshot` verifies that an
  emulator-only snapshot triggers a refresh and the subsequent USB phone is
  returned.
- `TestManagerShowsAndExecutesRefreshWhenNoUSBDeviceIsListed` verifies the
  visible retry row and its action.
- `TestFindADBExecutableHonorsOverrideAndSDKRoots/default macOS SDK root`
  verifies standard macOS SDK executable discovery.
- `CGO_ENABLED=0 go test ./plugins/android -count=1` passes.
- The focused related packages (`plugins/android`, `plugins/netfox`, `vfs`,
  `internal/plughost`, and `internal/fileops`) pass.

The full repository suite was also run. It still contains unrelated baseline
failures in `internal/app`, `internal/i18n`, `internal/panel`, and
`internal/theme`; the Android package and all Android regression tests pass.
