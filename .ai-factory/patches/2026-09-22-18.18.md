# Zoom dismisses the grouping submenu; adjoining menu edges

## Cause and fix

Zoom is custom content rather than a renderer choice, so its hover did not
participate in submenu dismissal. Add a passive HoverHandler to the complete
Zoom row: entering its background, Reset or slider clears the parent's active
row and closes Group by without intercepting clicks or drags.

Remove the explicit four-logical-pixel gap from both submenu opening directions.
Keep scene-space rounding, edge flipping and window-bound clamping.

## Verification

Both regressions failed first: Zoom left the submenu visible, and edge placement
measured a 4.08929-logical-pixel gap after snapping. They pass after the change.
Tests cover Zoom background/Reset/slider hover, no stale Group by highlight,
touching left/right edges, existing keyboard navigation and actual leaf alignment.
Scale-factor 1, 1.75 and 2 runs passed; inspected the 175% native-monitor capture.
Existing renderer ordering, zoom controls, static QML imports and diff whitespace
checks passed. Rebuilt static host, embedded payload and portable worktree binary.

## Prevention

Custom interactive sections must participate in menu hover state even when they
are not conventional menu items. Keep passive hover observation separate from
the controls' input handlers. No commit or push.
