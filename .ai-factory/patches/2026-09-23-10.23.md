# Make sticky group-header fades visible without hover

**Date:** 2026-09-23 10:23
**Files:** `third_party/ZoinGallery/qml/GalleryViewport.qml`, `third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp`
**Severity:** low

## Problem

Sticky group-header background fades were visible only while the pointer hovered over a header. In the resting state, the fade could not be seen against the panel background.

## Root Cause

The resting gradient used the panel background color over an area painted with the same color. The 175% render regression measured identical pixels (`#17191d`, RGB distance 0). The hover gradient used a distinct control-hover color, so it was the only state with visible contrast.

## Solution

Use a modestly lifted panel color (`Qt.lighter(headerColor, 1.2)`) for sticky headers only. Non-sticky headings retain the original panel color; both sticky background stops use the lifted color and continue fading to transparent. The regression captures the no-hover render and checks contrast at the solid edge and fade midpoint against the actual underlay. The stale visual assertion now reads the header's background color property rather than a removed `Item.color` property.

## Prevention

- Compare an unhovered sticky-header capture with the exact underlay, including the fade midpoint; a transparent endpoint alone does not prove the gradient is perceptible.
- Keep sticky-only styling conditional so ordinary group headings remain unchanged.
- Run the visual regression at 175% DPR and inspect the rendered capture.
