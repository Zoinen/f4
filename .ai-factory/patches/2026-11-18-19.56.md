# Keep plugin preview reads off the panel navigation path

**Date:** 2026-11-18 19:56
**Files:** internal/panel/directory_plugin.go, internal/panel/qt_semantic.go, internal/plughost/rpc_uri_media.go, sdk/f4vfs/uri.go
**Severity:** high

## Problem

In an iPhone DCIM panel, Qt kept responding locally while the Go event loop
could no longer handle commands or directory changes.

## Root Cause

The live size response called the plugin's path join synchronously to build
row IDs. The plugin's URI bridge serialized path and directory operations
with file reads under one lock. A stalled preview could therefore stop the
panel event loop.

## Solution

Build the rows from the listing and the published directory path, and defer
creating the preview mount until a media worker uses it. Resolve a directory
change on a worker, and keep bridge locks local to their mount or file.

## Prevention

Exercise Enter while the provider is waiting, and verify that a blocked read
can coexist with a directory operation and that registering a preview sends
no RPC requests.
