# Resolve paths typed in the Qt panel

**Date** 2026-11-23 14:36

**Files** `internal/panel/qt_path_input.go`, `qt/host/qml/GalleryPanelHost.qml`, `third_party/ZoinGallery/qml/PathControl.qml`

**Severity** medium

## Problem

A path pasted into the Qt panel editor could fail to open. A file target also needed to move the panel cursor and bring the row into view.

## Root Cause

The embedded path editor sent the same action for entered text and breadcrumb clicks. The core treated both actions as directory navigation. The viewport followed cursor changes, so a repeated file target with an unchanged cursor could remain offscreen.

## Solution

Send the raw editor text as a typed navigation action. Resolve local input on the background navigation lane, then use the normal directory load to apply the requested cursor. Publish a reveal revision so the viewport can also scroll to a cursor that has stayed on the same row.

## Prevention

Exercise a quoted Windows drive path that uses mixed slashes and targets a file. At 175 percent, verify that the viewport exposes the target after scrolling it away while leaving the cursor on it.
