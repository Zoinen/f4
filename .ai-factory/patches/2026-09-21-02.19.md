# Directory cache for remote panel re-entry

## Problem

Re-entering a NetFox directory after leaving it rebuilt the panel from the
cold placeholder. The panel did not retain the last successful directory
listing across VFS views, so remote rows were invisible until the next
`ReadDir` completed.

## Fix

- Added a bounded, panel-local read-through directory cache with copy-on-read,
  LRU eviction, and a maximum of 32 folders / 64K items.
- Added `vfs.DirectoryCacheKeyProvider` so providers can identify the
  configured remote independently of one short-lived VFS view.
- NetFox now uses a credential-free stable identity containing the configured
  connection and transport settings. SFTP, FISH+, and FTP clones preserve it.
- Android FISH and Sync views use the device serial as their stable identity.
- On a cache hit, rows are restored immediately and the fresh read starts with
  `IsLoading` still true. The authoritative result replaces/reconciles those
  rows and clears the loading indicator only when it completes.
- Added `[FIX:directory-cache]` and `[FIX:netfox-path]` diagnostics.

## Verification

- Regression-first test: `TestFileSystemPanel_RemoteDirectoryCacheShowsRowsWhileRefreshing`
  fails against the old behavior and passes after the fix while the backend is
  deliberately blocked.
- Passed:
  - `CGO_ENABLED=0 go test ./internal/panel -run TestFileSystemPanel_RemoteDirectoryCacheShowsRowsWhileRefreshing -count=1`
  - `CGO_ENABLED=0 go test ./plugins/netfox ./plugins/android ./vfs -count=1`
  - `CGO_ENABLED=0 go build -o .codex-build/f4-qt-cache-run ./cmd/f4`
- Live macOS run against `net://de_zoin/root`:
  - initial listing stored 16 entries;
  - after leaving to `net://de_zoin/`, returning produced a cache hit for 16
    entries immediately;
  - the fresh listing stored 16 entries about 206 ms later.

The complete `internal/panel` package still contains two pre-existing flaky
tests unrelated to this change. The no-op refresh failure reproduces on a clean
`HEAD` worktree; the row-free metadata revision test passes when run alone but
failed once in the package-wide run and passes on a standalone rerun
(`TestSameDirectoryRefreshKeepsCatalogDuringReadAndNoOpRevision` and the
row-free metadata revision assertion).
