# One active menu row and aligned Group by leading columns

## Problem

Hovering Group by opened the submenu without updating the parent's keyboard
index. The previous row stayed highlighted. Combining containsMouse with the
keyboard index could also highlight two submenu rows after keyboard navigation.
Group by omitted the checkmark slot, shifting its icon and title left.

## Fix

Opening Group by sets the parent active index. Each menu paints its highlight
from one index; hover and keyboard navigation both update it. Reserve the same
checkmark width and gaps as the other renderer rows, and bound the current-mode
label so it cannot overlap the title. Snap the actual changed text/icon leaves.
Use plain Images with one explicit correction transform: extending the aligned
image component appended a second correction rather than replacing the first.

## Verification

The pre-fix hover regression found the previous row still opaque (alpha 255
instead of 0). Extended tests cover native hover traversal, icon/title column
alignment, mouse-to-keyboard transitions, actual leaf pixel origins and unit
transforms. They also caught a duplicated correction at 99.5 physical pixels.

The final submenu test passed with scale factors 1, 1.75 and 2. The scale-factor-1
capture on the 175% monitor is 2450x1750 for a 1400x1000 window and was inspected.
Layout ordering, zoom controls, static QML imports and git diff --check passed.
Static host rebuilt, embedded payload regenerated, portable CGO-disabled launcher
rebuilt. No commit or push.

## Prevention

Keep hover and keyboard highlight state unified. Non-checkable submenu rows must
reserve the check column. Test pointer-to-keyboard transitions and actual leaves,
not just menu backgrounds. Future coverage can add repeated submenu reentry after
mouse and keyboard activation.
