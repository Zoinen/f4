# Fix: grouped header visuals and cross-group keyboard navigation

## Problem

Grouped Masonry headers used the gallery card border as their separator and a
non-Look-and-Feel chevron. The header content also placed the toggle glyph
before the group title. Near a group boundary, Up/Down could stop at the
header gap or use the list-view fallback at `x=0`, returning another entry
from the current group instead of preserving the horizontal keyboard anchor
across the boundary.

## Root cause

The shared pointer layer and the native visible-header model already owned
group hit testing, but the header delegate still inherited the card border
geometry. Masonry vertical navigation tried its ordinary `indexAt()` probe,
then the list-view fallback, before asking whether the probe had crossed a
group section. The fallback could therefore win inside the current group.

## Fix

- Render group headers with a normal rasterized Lucide `chevron-down` /
  `chevron-right` icon, with the title before the toggle icon.
- Replace the header border with one snapped top separator, reparented to the
  viewport root so it runs from edge to edge beyond the gallery content
  margins.
- Add a native `groupBoundaryIndex()` query that detects the section edge,
  skips collapsed groups, and resolves the destination at the preserved X
  coordinate.
- Run the group-boundary query before the list-view fallback, retaining the
  old source-order fallback only for non-boundary Masonry holes.
- Add opt-in `[FIX:group-header-navigation]` benchmark trace metadata.

## Regression coverage

- Header title/icon order, Lucide source, top-only edge-to-edge separator,
  sticky header geometry, and physical-pixel alignment.
- Up and Down transitions across both sides of a group header, including a
  partial Masonry row where the destination is not the first source index of
  the next group.
- Grouped mouse interaction regression remains covered.
