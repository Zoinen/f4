# Group header chevron was rasterized at double DPR

## Problem and root cause

The previous fix aligned the Image item but supplied physical pixels in its
sourceSize. Qt applies the window DPR to that property before calling the image
provider. At 175%, the regression measured a 44x44 request for a 25x25 physical
destination. Resampling distorted the chevron despite correct scene coordinates.

## Solution

Request the logical 14x14 source size; retain the snapped physical destination.
No runtime logging or extra rendering work is introduced. Regression failure
diagnostics report the requested and destination sizes.

## Verification

- New provider-size regression failed before the fix (44x44 versus 25x25).
- Added a physical one-pixel checker framebuffer comparison, covering texture
  resampling rather than only item origins and transforms.
- All five DPR CTest variants now include the complete header regression and
  passed at 100%, 125%, 150%, 175%, and 200%.
- Inspected a rendered 175% SVG chevron/title/count capture.
- Static Qt host rebuilt; qmlImportsWithoutInstalledQt passed; embedded payload
  regenerated and CGO-disabled portable worktree launcher rebuilt.
- Parent and Gallery diff whitespace checks passed.

## Prevention

Keep QML sourceSize in logical pixels, and test the actual provider request and
framebuffer at fractional DPR. Wrapper geometry checks cannot detect texture
resampling. Further useful coverage is moving the live window between monitors
with different DPR values.
