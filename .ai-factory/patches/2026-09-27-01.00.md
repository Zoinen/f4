# Keep deferred gallery work keyed by entry identity

**Date:** 2026-09-27
**Files:** `third_party/ZoinGallery/MasonryLayout.h`, `MasonryLayoutModelReset.cpp`, `tests/MasonryLayoutModesTest.cpp`, `README.md`
**Severity:** medium

## Problem

Warm iPhone folder reentry took 1.16–1.27 seconds to publish the last requested
thumbnail even though all 133 image reads hit the derived cache. One image was
ready at 259 ms but attached at 1156 ms.

## Root Cause

Incremental inserts shifted visible entries through many row positions before
the first scene swap. The facade queue retained each (row, entry ID) pair, and
invalid positions consumed the four-item budget before yielding another 8 ms.
Thumbnail planning was deferred until the live facade reached that queue.

## Solution

Queue each stable entry ID once and update its pending destination in place.
Reject inactive or replaced entries before charging the useful-work budget,
while retaining the wall-time limit, first-swap barrier and generation guards.
Keep masonry metadata row commits unchanged. Add opt-in
`[FIX:facade-queue-identity]` batch diagnostics.

## Verification

- The prefix-insertion facade convergence regression failed before the change
  with thumbnails disabled, isolating scheduling from I/O. It passes afterward
  for Grid and Masonry at DPR 1.75 (427/468 ms for the larger synthetic viewport).
- All 18 focused cases passed, including cached-thumbnail geometry gates,
  complete-row metadata commits, slot retention and rapid reset cancellation.
- Three fully warm live iPhone cycles published the same 35 requested thumbnails
  in 208.277, 207.345 and 208.699 ms. The next frame swaps occurred at 215.672,
  214.859 and 213.976 ms. Each cycle had 133 derived-cache hits and zero pixel
  decodes. Timings are from Go action receipt, with tracing enabled, not physical
  display-latency measurements.
- Cache, session, layout-engine and thumbnail-planner suites passed. The broader
  bridge suite had the same six failures with and without this fix (67 passed in
  each run). The architecture audit reports four unchanged oversized files;
  the Go panel suite also reproduces an unrelated unlistable-directory test
  failure in isolation. The plughost and iOS Go suites passed.

## Prevention

Bound useful work, not invalid queue records. When positions are mutable, update
the destination of an identity-keyed task rather than preserving every position
it once occupied. Exercise cached snapshots followed by incremental inserts
before the first rendered frame, and retain cancellation/recycled-slot tests.
