# Use a solid fill for sticky group-header backgrounds

**Date:** 2026-09-23 22:39
**Files:** `third_party/ZoinGallery/qml/GalleryPanel.qml`, `third_party/ZoinGallery/qml/GalleryViewport.qml`, `third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp`
**Severity:** low

## Problem

Sticky group headers had a vertical background gradient. After fixing its
transparency, the user preferred a plain color behind the pinned heading.

## Root Cause

The base header rectangle was still configured with multiple `GradientStop`
values, including a transparent endpoint. That was no longer the desired visual
contract for sticky headings.

## Solution

Replace the base rectangle's gradient with its solid `color` binding, retaining
the existing opaque, theme-derived sticky color. Give the separate hover layer
its own solid hover color as well, while keeping the top spacing outside its
interactive rectangle. Update the rendered regression to assert neither state
uses a gradient and that both fill colors cover the header at 175% DPR. Keep the
existing opt-in `[FIX:sticky-header-background]` benchmark trace for diagnostics.

## Prevention

- Validate visual style changes against captured framebuffer pixels, not only
  QML properties.
- Sample the complete sticky-header height to catch an accidentally transparent
  lower edge.
- Keep hover feedback as a separate solid-color layer; do not let it expose a
  gradient or extend into the noninteractive top spacing.
