# Unsupported panel fields in Qt row-free state updates

**Date:** 2026-09-20 13:17
**Files:** internal/nativeui/scene_incremental.go; internal/nativeui/incremental_test.go
**Severity:** high

## Problem

The Qt frontend terminated during startup with `Invalid or unbounded panel
state field`. The Go process then observed EOF from the external-UI host and
exited without a non-zero status, making the failure look like a silent
application exit.

## Root Cause

`BuildAppScenePatch` copied the complete row-free panel map into an incremental
`state_update`. That map also contained full-snapshot fields such as
`groupBy`, `groupFoldersSeparately`, `groupReverse`, `displayTop`, and `groups`.
The Qt host intentionally validates
`state_update` against a smaller bounded protocol contract and rejects unknown
keys before committing the patch. The merge exposed normal panel model changes
through this path, so the first startup redraw could terminate the host.

## Solution

Added an explicit Go-side allowlist for the Qt row-free panel-state contract.
Incremental patches now omit fields that belong to full snapshots or dedicated
catalog operations, while preserving the explicit Fast Find clearing fields.
Added `[FIX]` diagnostics that report omitted compatibility fields when a valid
state update is emitted, plus a regression test proving unsupported grouping
and layout fields cannot leak into `state_update` while supported state still
travels.

## Prevention

- Keep incremental protocol projections explicitly allowlisted rather than
  copying complete model maps.
- When the frontend validates a bounded operation, mirror that contract in the
  producer and update the producer test whenever the protocol changes.
- Exercise the embedded Qt host with a fresh payload cache after changes to
  semantic scene generation; Go unit tests alone do not prove the peer stays
  alive.
- Preserve a regression test for transient state clearing, such as Fast Find,
  whenever the projection is split into filtering helpers.
