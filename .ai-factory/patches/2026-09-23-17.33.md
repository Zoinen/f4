# Make the unhovered sticky group header opaque in the host

**Date:** 2026-09-23 17:33
**Files:** `third_party/ZoinGallery/qml/GalleryPanel.qml`, `third_party/ZoinGallery/qml/GalleryViewport.qml`, `qt/host/qml/GalleryPanelHost.qml`, `qt/host/qml/FilePanelView.qml`, `third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp`, `third_party/ZoinGallery/CMakeLists.txt`, `qt/host/tests/F4QuickViewSurfaceTests.cpp`, `qt/host/tests/TestGalleryPanel.qml`
**Severity:** medium

## Problem

In the Qt host, a sticky group header was transparent when not hovered. Panel content behind the header showed through its title, making the title difficult or impossible to read. Hovering appeared to fix it because the hover layer had a separate opaque color.

## Root Cause

The host intentionally supplies a fully transparent Gallery panel color. The earlier resting-state fix applied `Qt.lighter()` directly to that color; lightening preserves its zero alpha, so the resulting base gradient was also transparent. The standalone Gallery palette had obscured this host-specific condition in the earlier regression.

## Solution

Pass an opaque host-window backdrop into Gallery and composite the themed panel color over it before deriving the sticky-header base gradient. The sticky header now has an opaque region behind its labels and fades only below their rendered bounds; the hover layer remains separate. Extend the 175% visual test to start with a transparent panel color and verify the unhovered base alpha, title/count pixels, visible fade, and transparent endpoint. Existing opt-in benchmark tracing reports the resolved sticky background color.

## Prevention

- Exercise embedded-host themes that use transparent panel surfaces, not only standalone Gallery palettes.
- Assert the effective rendered background alpha and compare no-hover framebuffer pixels against the underlay.
- Keep the gradient opaque across every label/icon leaf and begin fading below their visual bounds.
- Run the rendered regression at fractional DPR, including 175%.
