# PDF zoom uses the current screen DPI

**Date** 2026-11-23 13:58

**Files** `GalleryPagePresentation.qml`, `GalleryViewerCatalogController.qml`, `ViewerMode.qml`, `F4QuickViewSurfaceTests.cpp`

**Severity** medium

## Problem

At 175% display scaling, the viewer showed a landscape A4 sheet at 100% in 842×595 device pixels. Qt reported 96 logical DPI, which calls for a 1965×1388 pixel canvas.

## Root Cause

Qt PDF provides the page dimensions in points. The viewer passed those values to a raster path that expects dimensions in device pixels and divides them by the window DPR for layout.

## Solution

Convert scalable page sizes at the presentation boundary using logical DPI × window DPR ÷ 72. Refresh the viewport when display metrics change, including when the page texture URL is reused.

## Prevention

Check the scene-space canvas dimensions and the rendered detail raster at 100% and 200%. Run the regression with DPR 1.75 at two logical DPI values. Keep a raster page in the test to verify its native pixel dimensions.
