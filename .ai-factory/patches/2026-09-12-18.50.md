# Qt terminal live progress, colors and bounded scrollback

**Date:** 2026-09-12
**Severity:** medium
**Files:** internal/terminal/child_env.go, internal/panel/qt_semantic.go, internal/panel/qt_semantic_incremental.go, qt/host/qml/DocumentWindowPresenter.qml, qt/host/qml/DocumentRowDelegate.qml, qt/host/qml/DocumentSurface.qml

## Problem

Rich progress did not reliably update, lost colors, hid the current bottom row,
and displayed oversized gaps between adjacent styled runs.

## Root Cause

The GUI terminal inherited TERM=dumb and NO_COLOR from the automation launcher.
Rich suppressed live refresh and colors before output reached F4. Independently,
the QML legacy row model retained stale nested run bindings on replacement. The
command-line overlay hid one active row even while a command was busy. Native
FontMetrics measured an 11-pixel advance for text actually painted at 7 pixels.

## Solution

Normalize dumb/unknown TERM for owned GUI terminals, retaining explicit NO_COLOR
preferences. Clear harness-only NO_COLOR on the development launch. Use the
existing native bounded row store for terminal windows and reuse run leaves by
count. Measure run advances using the actual Text renderer. Suppress the idle
prompt only when the terminal is not busy. Capability normalization is logged
through VTUI_DEBUG with a [FIX] prefix.

## Prevention

Regression-first checks reproduced failed environment declarations, stale text
and color updates, 11-vs-7 run advance, and missing busy bottom rows in both
full and incremental exports. Tests cover multiline ANSI rewrites, style-only
keys, colors in staging and permanent history, pinned scrollback, bounded row
writes, actual text leaf scene origins and unit transforms at DPR 1.75, plus
rendered capture inspection. Terminal fixtures now use the real shell surface.
The full document suite passes at DPR 1.75 (62 passed, 3 opt-in skipped).
Further coverage can vary Rich worker counts under rapid terminal resize.
