# Preserve Help text and link backgrounds while searching

**Date:** 2026-09-12 03:00
**Severity:** medium
**Files:** qt/host/qml/HelpContent.qml, third_party/vtui/help_view.go, internal/dialog/help_search.go

## Problem

Searching for `e` punched holes in the selected QML link background. Console
search overwrote adjacent characters, displaying `eelp` instead of `Help`.

## Root Cause

An inner rich-text span's transparent background replaced the enclosing link
brush. The console overlay separately reconstructed text geometry with a
one-column-smaller left inset, then wrote matching text at that wrong origin.
Centered text also used a different width and could escape the content range.

## Solution

Non-current QML matches set foreground only, preserving selection and hover
backgrounds. Console Help exposes its painted line origin and clipped width,
sharing the cell formatting/alignment implementation with normal rendering.
Search changes attributes on existing screen cells within that range, never
reconstructing or replacing characters. Existing [FIX:help-search] diagnostics
continue to cover search state without logging query contents.

## Prevention

The console regression recorded an H-to-e replacement at cell 7,3. It compares
all content characters before/after highlighting, including links, centering,
wide characters and clipped lines. The rendered QML regression at DPR 1.75
recorded #171e27 instead of the selected #285d8f background. Verify actual
pixels in addition to semantic match flags. Further coverage should include
overlapping matches and repeated renderer switches while searching.
