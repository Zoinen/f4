# Keep a visible frame during PDF file navigation

**Date** 2026-11-23 14:10

**Files** `GalleryPagePresentation.qml`, `GalleryViewerCatalogController.qml`, `ViewerMode.qml`, `F4QuickViewSurfaceTests.cpp`

**Severity** medium

## Problem

Switching PDF files could show a background-only frame while the new page rendered. The pre-fix regression observed an empty viewport source even though a cached first-page thumbnail was ready.

## Root Cause

The page controller clears its URL when a new document starts. The presentation treated the empty URL as a command to reset the viewport instead of a pending load.

## Solution

Use the current PDF's cached preview while fitting the page. Keep the previous frame during a pending load when the preview is unavailable or the viewer uses manual zoom. Replace the pixels and page geometry when the full frame arrives. Clear the viewport on render or password errors.

## Prevention

Hold the page renderer during navigation between real PDFs. Check the rendered thumbnail and pixel grid, test the pending state without a thumbnail, and verify the ready and error handoffs.
