# Project console Help search into QML

**Date:** 2026-09-12 02:10
**Files:** internal/dialog/help_semantic.go, internal/dialog/help_search.go, internal/nativeui/scene.go, third_party/vtui/semantic_help.go, qt/host/qml/HelpContent.qml
**Severity:** medium

## Problem

Typing in QML Help did not show the query, match highlighting or search hint.
The console search handler existed, but its rendering was a ScreenBuf overlay
outside HelpView's semantic node.

## Root Cause

Projecting HelpView alone missed application-owned render decorations. Search
navigation also calculated page size using console bounds, not the negotiated
native viewport.

## Solution

Project the existing search state at the common native dialog conversion used
by both full and incremental scenes. Clone visible rows/spans, split highlights
at Unicode rune boundaries while preserving links and bold text, and retain only
one authoritative search state. Use sorted match positions to skip offscreen
matches. Export the query in the common title and the localized footer hint.
HelpView centers search results using its active viewport capacity. Existing
keyboard handling remains shared. VTUI_DEBUG diagnostics use [FIX:help-search]
without recording query contents.

## Prevention

The Go regression failed on the missing title/query/hint; the QML regression
failed on the absent search footer before implementation. Cover Unicode across
format/link boundaries, next-match projection, stale topic state, owner snapshot
immutability, and small native viewports. Check actual footer and content text
leaves at DPR 1.75, including a rendered capture. Further coverage can exercise
translated hints and IME input with very narrow windows.
