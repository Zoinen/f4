# Gate masonry thumbnails on committed row geometry

## Problem

Known image dimensions and decoded thumbnail URLs could reach delegates before
the metadata-ready masonry row was committed. This affected ordinary operation
as well as the one-second diagnostic replay, including already cached URLs.

## Root cause

Metadata availability and committed geometry were separate, but publication
used only the image URL. Delaying decode requests alone cannot hide retained
URLs or protect recycled viewport delegates.

## Fix

Track publication readiness alongside existing brick geometry. Release it in
the complete-row commit, and expose it to the shared QML preview only after
delegate geometry has been installed. Close it before rebinding reused slots.
Only natural-size masonry gates the source; fixed modes bypass it. Readiness
itself counts as pending work so unchanged square geometry and terminal metadata
failures still release the gate. Reset and presentation changes revalidate rows.

## Regression

Before the fix, the publication test failed in ordinary and delayed masonry,
while all eight fixed-mode cases passed. Tests exercise a retained URL arriving
before metadata, fixed-mode switches, delayed cached reentry, and rows whose
settled dimensions do not change geometry. Run with DPR 1.75 alongside the
existing actual-leaf row geometry and rendered-image regression.

The expanded convergence regression also caught incremental sort/reorder paths:
they replace row boundaries without another metadata event. They now explicitly
schedule row revalidation. Final targeted run at DPR 1.75: 20 passed, 0 failed,
including catalog reorder, dense promotion, parent reentry, and sparse batches.

## Prevention

Never infer layout publication readiness from metadata or thumbnail availability.
Keep the barrier at the shared consumer so cache hits cannot bypass it, without
duplicating image data or slowing fixed-size presentations.
