# Preserve nonempty command input when Search-first focus moves to panels

**Date:** 2026-09-23 01:47
**Files:** `internal/panel/commandline_visibility.go`, `internal/panel/frame.go`, `internal/panel/commandline_visibility_test.go`, `internal/settings/catalog.go`, `internal/i18n/lang/{en,ru}.lng`, `docs/KEYMAP.md`
**Severity:** low

## Problem

With “Hide command input when unfocused” enabled, switching focus to a panel hid the command line even when it contained an unfinished command.

## Root Cause

The shared visibility predicate checked only the setting and focus. Both console layout and Qt semantic visibility inherited that result, so a nonempty edit was hidden.

## Solution

Hide only when the command edit is empty as well as unfocused. Reconcile actual visibility even when focus has not changed, because text can arrive while a previously empty input is hidden. Keep the setting's auto-hide capability unchanged, and log visibility transitions with `[FIX:command-line-visibility]` without logging command contents. Update the setting description and navigation documentation.

## Prevention

Test the visibility predicate through console rows and semantic Qt state with both empty and nonempty text. Also cover focus toggling while retaining an unfinished command.
