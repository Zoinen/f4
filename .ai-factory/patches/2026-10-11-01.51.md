# Keep same-entry gallery pixels during asynchronous resizing

**Date:** 2026-10-11 01:51
**Files:** third_party/ZoinGallery/GalleryDelegateItem.{h,cpp}, third_party/ZoinGallery/qml/GalleryEntryDelegateBase.qml, third_party/ZoinGallery/qml/GalleryEntryPreview.qml, third_party/ZoinGallery/qml/GalleryThumbnailCompactLayer.qml, third_party/ZoinGallery/qml/MasonryEntryDelegate.qml, third_party/ZoinGallery/tests/GalleryQmlInteractionTest.cpp, third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp, qt/host/tests/F4GalleryPointerTests.cpp, qt/host/tests/F4GalleryIconResizeFixture.h, qt/host/CMakeLists.txt, qt/host/README.md
**Severity:** medium

## Problem

Panel icons disappeared briefly while resizing the window. Compact thumbnails
could also disappear when their geometry-dependent source size changed. The
final ready frame looked correct, so a settled screenshot did not expose the
failure.

## Root Cause

Raster size changes start asynchronous image-provider requests. The Lucide
fallback and compact thumbnail did not retain the already displayed pixels
while those requests were loading. A rendered regression with the actual
F4IconProvider at DPR 1.75 measured 1,993 colored icon pixels before resizing
and zero during the loading frame.

Retention must be limited to the same stable entry ID. Viewport delegates are
pooled, so unconditional retention can paint the preceding file as a new entry.
Clearing an IconImage source is insufficient: Qt 6.11.1's implementation can
fall back to its previous internal URL when the source and theme name are empty.

## Solution

Enable Qt's retainWhileLoading for the existing icon and compact image leaves.
Publish a synchronous native identity-changing guard before replacement
snapshot notifications, and release it after the snapshot is committed. The
shared preview uses that guard to unload its image leaves only on reassignment.
A synchronous Loader owns the fallback IconImage, preserving its SVG tinting
and destroying the old leaf even when the new entry uses the same icon URL.
Same-entry geometry and metadata changes keep the existing image leaf.

Keep pixel correction on the centered Loader, where x/y are observable binding
dependencies. Applying it to an anchored child instead missed changes in the
new parent's position and caused half-physical-pixel origins after resizing.
The child receives exactly one correction through its parent, with unit scale.
No second application image cache, timer, duplicate image, or catalog rebuild
is introduced. Existing opt-in benchmark tracing reports identity resets.

## Prevention

- Capture intermediate Loading frames with a deliberately blocked provider;
  do not validate asynchronous visual fixes only after Ready.
- Test same-entry retention separately from delegate replacement, including
  replacement with the same source URL and completion of preceding requests.
- Inspect the active Loader item, not a retired QObject awaiting deletion.
- Locate semantic visual leaves by stable objectName rather than the first
  sibling with a color property or a fixed number of parent hops. Diagnostic
  overlays and lifecycle wrappers must not invalidate behavior assertions.
- Verify the actual rendered leaf's physical origin, extent, and unit transform
  at fractional DPR after both resizing and replacement.
- Preserve standalone Gallery tinting when changing f4's icon loading path.

The seven rendered regression rows and the native notification-order regression
pass. F4GalleryPreviewResizeDpr175Test registers the rendered checks in CTest.
