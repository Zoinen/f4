# Settings category drag selection and icons

## Root cause

The category sidebar is a semantic table with one column and no header. Its QML
row MouseArea selected only on click/release and allowed an ancestor Flickable
to take the drag. Row-owned handlers also cannot reliably keep gestures across
semantic row replacement. A TapHandler exclusive grab alone was insufficient:
Qt's Flickable child event filter can steal it without respecting handler-only
grab permissions.

## Fix

`SemanticListPointer.qml` is shared by listboxes and table bodies. Mouse press
selects immediately; a mouse-only, zero-threshold DragHandler keeps the viewport
grab, routes Y-based selection, and suppresses duplicate indices within a drag.
The persistent controller excludes the scrollbar/header. Captured sideways
motion selects by Y; vertical exit does not select or scroll. Touch tap/flick,
wheel, scrollbar and table double-click activation retain separate handling.

The Settings owner exports typed `itemIcons` metadata in category display order,
keyed by stable category ID. Qt renders the optional icon before the caption
without increasing row height. All 18 core categories are covered, with file-cog
for contributions. The unchanged Lucide 1.27.0 keyboard SVG was added to both
the resource manifest and the icon provider's supported-name set.

## Regression and verification

- Before: pressing row 1 emitted no selection. The first attempted TapHandler
  fix lost its grab on row 0 during held movement; sideways selection then failed.
- After: both listbox and category-table sequences are 1, 3, 2, 0, 3, 2 with full
  semantic acknowledgements; the outer dialog's scroll offset stays unchanged.
- Touch scrolling/tapping, wheel, scrollbar, disabled/read-only input and
  non-activating drag are covered. Initial geometry is settled before wheel input.
- Every category icon and caption, including optional list icons, is checked for
  scene-space physical-pixel origin and unit transform at DPR 1.75. A captured
  frame using the production raster provider was inspected. The test also caught
  keyboard being normalized to file before the supported-name set was extended.
- All Go packages passed. Qt operations/dialog suite: 41 passed, 1 opt-in profile
  skipped. Document suite: 61 passed, 3 skipped. Static QML imports and compiled
  production-host smoke passed; imports contain only Windows system DLLs.
- A fresh embedded candidate was launched and its extracted host hash matched
  the native build before replacing the worktree application. Launched Qt directly.

## Prevention

Test gestures across semantic updates, not only clicks on fixed fixtures. Use
the actual semantic kind (Settings categories are a table). Validate embedded
assets through the production icon provider, since raw SVG test doubles cannot
detect name-normalization fallback or verify final tint/rasterization.
