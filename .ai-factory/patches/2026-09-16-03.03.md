# Restore cached catalog geometry before publication

**Date:** 2026-09-16 03:03
**Files:** third_party/ZoinGallery/{ThumbnailLoader,DecodeManager,PersistentDerivedImageCache}.{cpp,h}; Runners/CacheImageRunners.{cpp,h}; src/embed/ExternalCatalog{Model,Metadata,ResetTransaction,Decode}.cpp; qml/GalleryFolderPreview.qml; GallerySessionTest.cpp; PersistentDerivedImageCacheTest.cpp; qt/host/README.md
**Severity:** high

## Problem

Repeated navigation between `P:\[Year 2026]` and `[2026] 4A` delayed folder
collages and progressively rebuilt the image layout. Scrolling fetched dimensions
again despite the catalog containing only 355 JPEGs. Six baseline navigation
cycles reproduced 1,249–1,457 ms metadata completion and zero metadata cache hits.

## Root Cause

- All 355 JPEGs have EXIF without an Orientation tag. TinyEXIF returned zero,
  which the decoder propagated. The versioned metadata cache correctly rejected
  this invalid orientation, so each visit read the source again.
- Versioned metadata had no memory tier. Even a disk hit required manifest access
  on the Qt event loop, after initial catalog publication.
- Deferred display metadata discarded the byte size already supplied by F4's
  authoritative image descriptor. Later path/timestamp enrichment invalidated
  geometry for the same opaque resource revision.
- Folder presentation waited for fresh QML Image.Ready signals even when the
  retained child model already owned published thumbnails.
- An initial memory-cache implementation still resolved the OS cache/temp path
  for every key. Profiling isolated roughly 253 ms of catalog reconciliation to
  these repeated OS queries.

## Solution

Normalize absent/invalid metadata orientation to unrotated. Add a shared, bounded
16 MiB metadata memory tier using the existing revision, byte-size and authority
keys. Copy only derived values into the requesting descriptor; retain no leases
or request namespace. Memoize the immutable storage root. Clear the tier with
image-cache maintenance.

Restore cached dimensions while installing catalog rows, including sparse pages.
Preserve authoritative byte size while deferring display fields. Preserve geometry
through path/timestamp enrichment of an unchanged opaque revision. Queue cold
manifest reads on the existing bounded cache worker with namespace cancellation.
Expose retained thumbnail-publication state so folder frames restore immediately.
Existing opt-in media traces distinguish memory restores and worker disk lookups.

## Regression checks and measurements

- Before fixes: JPEG orientation was 0 instead of 1; cached catalog dimensions
  were absent; retained publication state was false; disk lookup emitted its
  completion synchronously. The same regression checks now pass.
- Eight final navigation cycles restored all 355 dimensions in 73.5–95.3 ms from
  Enter. The first visible rows restored in 8–10 ms. Catalog reconciliation took
  5.2–5.8 ms. Warm entries performed zero metadata source reads, disk metadata
  lookups or source pixel decodes.
- Long scroll passes additionally warmed previously unseen images. Two final
  passes to the bottom then produced only memory hits: zero metadata reads or
  source decodes. QML provider lookup median was 0.025 ms, 95th percentile 0.040 ms
  (lookup time excludes texture upload and rendering).
- Trace and input marks: `.diagnostics/cache-nav-before-profile.*`,
  `cache-nav-fast-profile.*`, and `cache-nav-full-scroll-settled.*`.
- Passed CTests: QtMediaClientTest, ThumbnailMemoryCacheTest,

  MasonryVisualDpr175Test. Focused F4 bridge and static QML-resource checks passed.
- Actual folder thumbnail/text leaf origins, unit-vector transforms and clipping
  passed at DPR 1.75; captured filename, thumbnails and strokes were inspected.
- Relevant Go directory/media tests, Windows system-DLL import audit and generated

## Prevention

Use real metadata variants, including valid EXIF without Orientation, in cache
regressions. Exercise F4's deferred opaque descriptors rather than only legacy
local-path catalogs. Check cached dimensions at catalog publication and again
after display metadata enrichment. Profile nominal memory-hit paths for hidden
OS calls. Separate retained presentation state from newly created image-widget
readiness. Keep a cold disk-hit responsiveness regression alongside warm tests.
