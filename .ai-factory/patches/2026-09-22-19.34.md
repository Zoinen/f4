# Grouped overflow and clearing header delegates

## Root cause

Masonry's legacy overflow check repacked all bricks as an ungrouped list.
Section headers and forced section row breaks were ignored, so a genuinely
overflowing grouped panel could report needScroll=false. Separately, setGroups
notified descriptors but not visibleGroupHeaders. The ungrouped rewrap path
does not publish headers, leaving old QML Repeater delegates visible after Off.
The earlier minimum-thumb change addressed only a separate usability issue.

## Solution

Use the already computed grouped content extent for overflow detection, as
fixed and sparse layouts already do. Notify the header model when descriptors
change, including the transition to an empty group index.

## Verification

New groupedOverflowAndDisabling data cases failed before implementation:
needScroll was false for overflowing sections; five rendered headers remained
after descriptors were cleared. Both now pass. Grouped rendering, keyboard
navigation, mouse interaction, vertical scrollbar and sparse Details checks
passed at DPR 1.75 (nine results including setup/cleanup). Five host test
results passed, including static QML imports and menu/splitter interaction.
Rebuilt the static host, embedded payload, and portable worktree launcher.

## Prevention

Test transitions through actual QML header delegates, not only the native
getter. Overflow tests must include catalogs that fit ungrouped but overflow
when split into sections. Reuse section geometry instead of repacking it.
