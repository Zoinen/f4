# Settings sidebar input and chrome boundaries

**Date:** 2026-10-20 02:17
**Files:** qt/host/qml/SettingsDialogBody.qml, qt/host/qml/SemanticListPointer.qml, qt/host/qml/SemanticWidgetDelegate.qml, qt/host/qml/F4TextField.qml, qt/host/qml/DialogTextField.qml, qt/host/qml/GenericDialog.qml, qt/host/tests/F4OperationsQueueTests.cpp
**Severity:** medium

## Problem

Settings category wheel input changed pages; category scrollbar had an outer
right gutter, and the sidebar fill overpainted the bottom border. Search actions
were framed controls outside a shrinking input. Flat traffic lights did not
match the native macOS reference supplied by the user.

## Root Cause

The shared table pointer inherited console-oriented semantic wheel selection.
Disabling it alone left pixel-only wheel sequences unsupported by the generic
Flickable path. Geometry reserved toolbar space next to search rather than in
the field, and sidebar background height included the border's final pixel.
The original chrome used flat 12-pixel circles and oversized opaque symbols.

## Solution

Settings navigation consumes wheel and touchpad deltas into bounded local
contentY without selection actions or additional synthesized momentum. Native
drag/tap/keyboard selection remains unchanged. Geometry places the scrollbar at
the sidebar edge and stops the fill before the bottom border. Passive model
updates preserve the viewport offset.

Search reserves explicit leading/trailing text insets. Clear replaces the
magnifier and next/previous share the field as flat icon controls with original
semantic IDs and accessible descriptions. Clearing restores the original icon
and insets without changing width.

Traffic lights use 14-pixel antialiased circles, one-physical-pixel rims,
subtle gradients, neutral disabled colors and translucent hover-only symbols.
Windows chrome and modal capabilities are retained. Optional wheel tracing uses
`traceWheel` and `[FIX:settings-scroll]`, disabled by default.

## Prevention

The pre-fix regression failed for wheel scrolling and search-button containment.
Verify mouse notches and pixel-only begin/update/end sequences independently;
assert no category action is emitted and passive updates retain scroll. Measure
scrollbar and sidebar edges in the dialog coordinate system. Exercise clear and
match-navigation clicks inside the text field plus inactive-search restoration.
Test fractional-DPR chrome geometry and antialiasing against a native reference,
and wait for the alignment polish pass before asserting painted glyph origins.

Final verification: the offscreen Qt dialog suite passed 77 tests with two
opt-in skips at 175%; the three focused regressions also passed on native Cocoa.
The Qt host built successfully and no live Settings draft or profile was changed.
