# Double-click parent navigation preserves the destination selection

## Problem

In a NetFox panel at `net://de_zoin/root`, double-clicking `..` navigated to
the parent directory but could leave the folder just left unselected. Enter
worked because it did not emit an extra cursor intent after opening.

## Root Cause

The second press of a native double-click used the normal pointer-selection
path and armed `cursorCommitPending`. Qt then emitted `doubleClicked`, which
sent the stable `panel.open` intent. On release, the still-pending cursor
commit emitted a stale `panel.cursor` after `panel.open`, racing the
destination catalog and its pending parent selection.

## Solution

When `GalleryNavigationController.selectIndex` opens an item, cancel the local
deferred cursor commit and both commit timers before dispatching the stable
open request. The open already carries the stable entry ID, so the deferred
cursor is redundant and unsafe. A gated `[FIX:double-click-open]` diagnostic
logs the canceled entry ID.

## Regression Evidence

The existing double-click timing test was extended to require zero
`panel.cursor` actions after `panel.open`. Before the fix it failed with one
post-open cursor action; after the fix it passed. Related stale-loader/focus
and non-current-image double-click tests also pass.

## Prevention

Keep pointer-selection commits and stable open intents mutually exclusive once
an open gesture has been recognized. Test action ordering, not only whether an
open action eventually appears.
