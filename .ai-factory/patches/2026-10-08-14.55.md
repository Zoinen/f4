# Keep clipped settings text inside the screenshot viewport

**Date:** 2026-10-08 14:55 MSK
**Files:** `qt/host/tests/F4QuickViewSurfaceTests.cpp`
**Severity:** medium

## Problem

The portable Linux CTest gate failed on both amd64 and arm64 in
`F4GalleryVideoSettingsPixelGridTest`: `galleryQuickVideoPlaybackModeText`
was reported as rendering no visible glyphs.

## Root Cause

The test captured the whole settings page while its native settings viewport is
a clipped `Flickable`. The last video-mode text item remained `visible`, but
could extend below the viewport, so the window screenshot contained only the
underlying background in that item's crop. The test checked window bounds and
pixel-grid geometry, but not whether the text was inside the clipping viewport.

## Solution

Expand the offscreen test window enough to show the entire gallery settings
page, assert the affected text lies inside the native viewport, then run the
existing 175% scene-coordinate and rendered-pixel checks.

## Prevention

- `QQuickItem::isVisible()` does not account for clipping by ancestors.
- Rendered-text checks inside scroll or flickable content must ensure the leaf
  is within the viewport (or scroll it into view) before inspecting pixels.
- Keep the final scene-transform and rendered-image checks after resizing or
  scrolling so the test still validates the resting layout.
