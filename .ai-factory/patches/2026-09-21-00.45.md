# NetFox path, history, and panel-cache fix

## Problem

NetFox connections exposed the remote POSIX path directly. Leaving a
connection therefore produced history entries such as `/home/user`, which
could later be mistaken for a local folder. The connection path was also not
available to the URI restore path, and opened SFTP/FTP sessions did not expose
the same cached panel-information provider used by Android.

## Fix

- Publish opened NetFox sessions as `net://<connection>/<remote-path>` while
  continuing to send only the decoded remote path to SFTP, FTP, or FISH+.
- Preserve the qualified path through `GetPath`, `Abs`, `Join`, `Base`, `Dir`,
  command execution, mutations, clones, and server-side operations.
- Register a `net://` URI provider so folder history and other persisted paths
  can reopen a saved connection and restore its remote directory.
- Attach shared, read-through `PanelInfoProvider` caches to the NetFox manager
  and opened SFTP/FTP/FISH+ backends, with local connection facts immediately
  available to the information panel and reused by clones.
- Add regression tests for URI authority preservation, qualified backend paths,
  cache availability, URI restoration, and folder-history eligibility.
