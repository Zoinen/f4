# Keep File groups vertical navigation inside the editor

**Date:** 2026-10-18 19:59
**Files:** internal/settings/center.go, internal/settings/file_groups_test.go,
docs/SETTINGS_CENTER.md
**Severity:** medium

## Problem

Repeated Up/Down in File groups eventually moved focus into global Settings
search/categories or the footer, interrupting editing.

## Root Cause

The compound editor inherited the generic scalar-page boundary policy: an
unhandled Up at the first control focuses search and Down at the last control
focuses Apply. The next Down can then move from search into categories.

## Solution

Keep unhandled vertical boundary arrows local to the File groups page after
its controls have processed navigation. Preserve Tab/Shift+Tab, editing keys,
and existing navigation in other categories. Opt-in VTUI_DEBUG diagnostics use
[FIX:file-groups-focus]. No profile data or Qt protocol changes are required.

## Verification

The regression first failed with Up escaping to *vtui.Edit. The same test passes
after the fix and checks repeated arrows in both directions and explicit Tab
exit. Related Settings tests and the CGO_ENABLED=0 application build are run.

## Prevention

Test compound-editor boundaries separately from scalar-form boundaries, including
repeated keys rather than only one transition. Additional useful coverage is
native Qt key-repeat with dropdowns and multiline command fields focused.
