# Directory size cache lookup cost during held-Enter navigation

**Date:** 2026-11-06 13:52 Europe/Moscow
**Files:** internal/panel/list_size.go, list.go, list_size_cache_test.go, list_size_benchmark_test.go; docs/FILE_FIELDS.md
**Severity:** low

## Problem

The user reported slow repeated Enter navigation after adding the recursive
directory size cache and asked whether it introduced synchronous work.

## Root Cause

F3 scanning and directory reads run on background tasks/workers. Applying ready
cached sizes is synchronous, including for UI-installed listings. The original
flat map constructed and normalized every full child path while holding the
cache mutex. It allocated two strings per directory, including for cache misses.

This cost does not explain the reported small-folder latency. Serial native
Qt/Metal ABBA measurements used the same current Qt host and the pre-change Go
sources from the saved worktree snapshot. The current comparison binary populated
the size cache before warmup via a diagnostic-only Go overlay. The 80 measured
transitions per version averaged 95.208 ms before the feature and 96.051 ms with
the populated cache (medians 95.007 and 95.636 ms). Enter means were 97.554 vs
96.761 ms; leave means 92.862 vs 95.341 ms. These runs do not demonstrate a
material navigation regression from the size feature.

The actual directory read completes around 1 ms. The correlated trace shows UI
scene export delaying metadata/final tasks to around 74 ms. The CPU profile of
the comparison run attributes about 40% of samples to file-group icon predicates
and roughly 58% to renderPhase. Those existing scene/icon costs are distinct
from size-cache lookup. The automated runner measures action-to-ready-frame,
including cursor placement; it does not measure the OS keyboard-repeat interval.

## Solution

Use one parent bucket per qualified directory and name-keyed child totals.
Normalize the parent once outside the mutex; never call the backend under the
cache lock. Clone stored basenames to avoid retaining full descendant paths.
Keep the empty-cache fast path and return immediately on an unmeasured parent.

The regression check failed first with 20 Abs calls under the lock; it now
requires at most one call outside it and verifies all cached values survive.

## Measurements

Five serial 200 ms microbenchmark samples, median ns/op, same host:

| Directory children | Before | After | Restore allocations before/after |
| --- | ---: | ---: | ---: |
| 20 | 5,733 | 217 | 40 / 0 |
| 128 | 33,471 | 820 | 256 / 0 |
| 10,000 | 2,564,697 | 96,617 | 20,000 / 0 |

Raw before/after microbenchmarks are in `/tmp/f4-size-restore-before.txt` and
`/tmp/f4-size-restore-after.txt`. Native A/B traces, profiles, overlays and analyzer
summaries are in `.diagnostics/size-navigation/native-*`. Offscreen pilot runs
failed before runner actions because native macOS menu setup requires Cocoa;
they are excluded from all latency statistics.

## Prevention

Profile the complete input-to-frame path before blaming new caching work.
Measure filled-cache navigation explicitly: normal runner warmup never invokes
F3. Keep cache restores free of per-child path construction and VFS methods
under the lock. Preserve raw samples and compare builds serially on one host.

## Verification

- `TestDirectorySizeRestoreResolvesParentOnceOutsideCacheLock` failed before the
  optimization and passes afterwards; all existing cache/navigation/F3 tests
  remain enabled.
- Full `CGO_ENABLED=0` panel and app suites pass; the worktree Go binary builds.
- Post-optimization native runner: enter 94.722 ms, leave 95.061 ms (40 measured
  transitions); its control baseline: enter 95.634 ms, leave 93.873 ms. Overall
  means are 94.891 vs 94.754 ms. The small cache optimization therefore does not
  address the existing roughly 95 ms scene/paint latency.
- One post-optimization native pilot timed out during warmup before any measured
  transition and is excluded; the repeated run completed all cycles. The core
  can exit successfully even when the host runner reports failure, so completed
  transition records, not just subprocess exit codes, are the validation gate.
