# Folder previews must cross the real media boundary

**Date:** 2026-09-15
**Files:** qt/host/src/QtMediaClientWire.cpp, F4DirectoryPreviewProvider.cpp, F4GallerySourceDescriptor.h, F4GalleryBridgeCatalog.cpp; qt/host/tests/QtMediaClientTests.cpp; third_party/ZoinGallery/Decoders/RawDecoder.cpp, RawBitmapPreview.h, tests/GallerySessionTest.cpp
**Severity:** high

## Problem

No folder thumbnails appeared in P:\[Year 2026] despite fixture-based Gallery tests passing.

## Root Cause

The media encoder serialized QStringList as a string. Go rejected the resolve
request as stale because names was not an array. Once corrected, preview entries
still carried nested Go source descriptors; Gallery expects flattened source
fields. Fixtures supplying localPath bypassed both adapter contracts.

Small RAW preview requests exposed a third existing assumption: LibRaw bitmap
thumbnails were labeled JPEG. A 131328-byte RGB thumbnail failed JPEG decoding,
while requesting a larger embedded JPEG from the same DNG succeeded.

## Solution

Encode QStringList and QVariantList as MessagePack arrays. Reuse one descriptor
normalizer in the ordinary catalog bridge and directory adapter. Extend the
socket test through the actual adapter enumerate/resolve/ACK sequence, including
Unicode names and the child resource/version fields. Distinguish LibRaw bitmap
and JPEG output, converting 8/16-bit bitmap samples to a PNG preview.

## Prevention

Exercise real adapter boundaries, not only local-path fixtures. The wire test
failed with names type 10 instead of 9; the adapter test failed with empty
resourceId. Both now pass. A runtime DNG regression failed JPEG decoding before
the RAW fix and passes afterward. Synthetic RGB/grayscale and truncated-buffer
checks run without private media; the real RAW test is opt-in via
F4_TEST_RAW_PREVIEW. Full GallerySessionTest and QtMediaClientTests passed,
as did static QML, Windows import and generated payload checks.

The final live window was captured with folder collages visible. Its diagnostic
run recorded 122 successful decode completions and no failed completions.
