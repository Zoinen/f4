# Panel dropdowns switch on hover while a menu is open

## Cause and fix

Sort and View buttons only opened their dropdowns on clicks. Their outside-click
dismiss planes cover the header while a popup is open, so observing hover on the
buttons (or below those planes) is insufficient. Enable hover observation on the
existing dismiss planes and map the pointer into the two button rectangles.
Close the old dropdown and open the hovered sibling. Switching away from View
also closes its Group by submenu. No menu opens from hover when both are closed.

Guard deferred focus restoration against an open sibling so closing one menu
cannot steal focus from the newly opened one. No visual geometry changes.

## Verification

The pre-fix native-pointer regression failed when hovering View after opening
Sort. It now passes both directions, nested Group by closure, Escape dismissal,
and idle hover without opening. The related submenu, Zoom hover/control, renderer
ordering and static QML import tests all passed (8 QtTest results). The suite was
also run with QT_SCALE_FACTOR=1.75. git diff --check passed. Rebuilt static host,
embedded payload and CGO-disabled worktree launcher. No commit or push.

## Prevention

Test menu-bar semantics through the actual overlay hit-test stack, not by directly
invoking button handlers. Check deferred focus restoration during menu handoff.
