# Exclude panel scrollbars from native file drag hit testing

## Problem

Dragging a panel scrollbar could prepare and start a file drag.

## Root Cause

The native window event filter runs before QML dispatches the press to the
scrollbar. Its file hit test used layout geometry without excluding scrollbar
overlays, so it could arm the file underneath the pressed control.

## Solution

Expose the two existing scrollbar items through Gallery's panel surface. The
host maps the pointer into each visible, enabled scrollbar and rejects those
hits before resolving a file. This covers both vertical and Columns scrolling
without fixed-width guesses or per-entry scans. Diagnostic tracing remains
behind the existing benchmark switch.

## Prevention

Overlay controls must take priority in native hit tests, not just QML event
delivery. The existing native drag integration test now checks scrollbar
press/move/release in every panel layout and rejects prepareDrag requests.

## Verification

The extended native drag integration test passed at DPR 1.75 in all five
layouts. The static QML import test and both repositories' diff checks passed.
Rebuilt the static host and embedded Go executable; a fresh extraction opened
a responding `f4 [zoin]` window, with the extracted host hash matching the build.
