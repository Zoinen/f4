# Restore Masonry zoom steps and slider gestures

**Date** 2026-11-19 18:29
**Files** ZoinGallery Masonry layout, Qt panel chrome and pointer regressions
**Severity** medium

## Problem

Reversing Ctrl-wheel at maximum Masonry zoom jumped from 500 to 44 pixels. Dragging the zoom slider could start a native file drag from the panel underneath.

## Root cause

The zoom scan sized its synthetic catalog at the starting height. As the candidate height decreased, the catalog ran out of entries before the next row could wrap. The fallback added bottom viewport padding to the minimum density. The native window event filter also performed file hit testing before Qt Quick could deliver the press to the popup.

## Solution

Compute the reference row capacity from the same width and spacing rules as the Masonry layout. Use the current thumbnail's aspect ratio when available. Scan density directly and choose the adjacent capacity range. Disable panel drag and drop hit testing on both sides while a panel menu owns pointer input.

## Prevention

Test zoom from the upper bound with bottom padding and with portrait thumbnails. Send Ctrl-wheel events through the embedded gallery. Check both panels' drag gates while dragging the slider and after closing the menu.
