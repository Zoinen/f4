# Preserve live image facades across incremental catalog reconciliation

**Date:** 2026-09-11 23:59
**Files:** third_party/ZoinGallery/src/embed/ExternalCatalogResetTransaction.cpp, third_party/ZoinGallery/src/embed/ExternalCatalogResetTransaction.h, third_party/ZoinGallery/MasonryLayoutThumbnails.cpp, third_party/ZoinGallery/tests/GallerySessionTest.cpp, third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp
**Severity:** high

## Problem

Four consecutive Photos entries remained icon placeholders indefinitely in
the left masonry panel. Scrolling away and back did not repair them. The
source JPEGs were readable and layout aspect ratios were correct.

## Root Cause

Incremental reconciliation staged entries before emitting Qt row signals.
An observer of a later insertion could rewrap the viewport and materialize
ImageFile facades for earlier rows. Those objects existed only in the live
model. Committing the staged list over the live list discarded their pointers,
leaving delegates attached to orphan facades that never received metadata.

Tracing proved the difference: the model had widths 3984/2956/3984 for the
missing images while their bound facades still had width -1. The decode
planner therefore rejected them before queue admission. The consecutive
appearance was a consequence of viewport materialization during row delivery,
not a broken JPEG decoder or a missing geometry band.

## Solution

Keep the reconciled live entry list authoritative for incremental commits;
ordinary reset transactions still install their staged list. Rebuild the
provider inverse index from committed entries. Add opt-in trace events for
preserved observer-created facades and thumbnail-plan rejection reasons,
using F4_MEDIA_TIMING_TRACE and [FIX:incremental-facade-retention].

The focused regression materializes four earlier rows from a later
rowsInserted observer, checks pointer identity after commit, delivers metadata,
and checks the same objects receive dimensions without leaving orphan objects.
It failed before the fix and passes afterward. The two-panel QML smoke test
also exercises provisional enumeration, reorder, scrolling, synthetic PNGs,
real JPEGs through ZOIN_THUMBNAIL_REGRESSION_DIR, and DPR 1.75.

## Prevention

- Treat synchronous Qt row observers as reentrant: even reading a lazy role
  can mutate the model's materialized state.
- Do not overwrite observer-visible runtime state with pre-signal snapshots.
- Cover creation during later-row callbacks, not only facade creation before
  the transaction or sorting a fully materialized catalog.
- Additional coverage should exercise metadata/cache-hit publication from
  the currently moved row's callback; its per-row replacement remains a
  separate reentrancy risk.
- Baseline comparison matters: the existing
  masonryCatalogResetRetainsSlotsAndBoundsMaterialization geometry assertion
  failed identically with and without this fix. The unchanged Go panel test
  TestSameDirectoryRefreshKeepsCatalogDuringReadAndNoOpRevision also fails
  independently because its supposedly unchanged row acquires real metadata.
