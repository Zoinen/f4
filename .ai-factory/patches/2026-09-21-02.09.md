# Patch: preserve thumbnails across grouped catalog relayouts

## Observed failure

Changing Group by can reorder a sparse external catalog and emit a model reset.
The reset path used to cancel every runner, detach every published thumbnail,
and retire every materialized `ImageFile`, even when an entry with the same
stable identity and source revision was still present. Folder preview demand
was also stored only as row numbers, so a reorder could retire a demanded
folder preview when its row moved.

## Correction

- Retain sparse entries by stable `entryId` when the catalog is equivalent.
- Preserve the materialized `ImageFile`, decoded metadata, thumbnail provider
  identity, and pending source-keyed work for unchanged sources.
- Cancel and retire only removed or source-changed entries.
- Track directory-preview demand by stable entry identity and resolve its row
  after catalog changes.
- Keep an opt-in `[FIX:group-layout-thumbnail-retention]` timing event for
  diagnosing retention counts without adding normal-runtime logging.

## Regression guard

Keep coverage for both direct sparse catalog reorder retention and folder
preview demand across a parent-catalog reorder. Layout/group changes must not
be treated as a thumbnail invalidation or source re-read request.
