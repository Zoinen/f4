# Fast Find semantic dismissal

Date: 2026-09-19

## Summary

Fixed a Qt panels bug where the Fast Find field could remain visible after the
Go-side search mode had already been cancelled. The stale field ignored later
cursor movement and pointer interaction because input was no longer routed to
Fast Find, while QML still retained the previous semantic panel descriptor.

## Root cause

`PanelsFrame.CancelFastFind` cleared only panels whose `FastFindMode` flag was
set. It did not clear a residual query when the flag had already been reset,
and it did not invalidate the semantic scene. If an action or focus transition
replaced the active presentation before a full redraw, a later compact
cursor/activation update could preserve the old QML `fastFind` state.

## Changes

- Clear both active Fast Find mode and residual query text on every panel.
- Invalidate the semantic scene whenever cancellation changes Fast Find state.
- Add gated `[FIX:fast-find-dismiss]` diagnostic logging.
- Add a regression test that checks both residual-state cleanup and semantic
  invalidation.

## Regression evidence

Before the implementation, the new test failed with:

```text
Fast Find state survived cancellation: left=false/"" right="stale"
```

After the implementation, the regression and related suites pass:

```text
go test ./internal/panel -run '^TestPanelsFrame_CancelFastFindInvalidatesSemanticScene$' -count=1
go test ./internal/panel -run 'FastFind|SemanticPointerIntentsClearFastFind|PanelActivationFastPath' -count=1
go test ./internal/app -run 'FastFind' -count=1
go test ./internal/nativeui -run 'FastFind' -count=1
```

## Build and live verification

- Built the Linux arm64 launcher with `CGO_ENABLED=0`, `goffi_static`, and
  `f4_embedded_qt_host`.
- `ci/audit-static-go-linux.sh f4.new` confirmed a static ELF with no
  interpreter or `DT_NEEDED` entries.
- Relaunched the Qt frontend with hardware rendering enabled.
- Live-tested Fast Find with `kwin_wayland`, invoked F3, and then moved the
  selection with an arrow key. The field disappeared immediately and did not
  return during navigation.

## Unrelated baseline

The full `internal/panel` package still has an unrelated pre-existing failure
in `TestSameDirectoryRefreshKeepsCatalogDuringReadAndNoOpRevision`; it concerns
catalog object identity during metadata refresh and does not exercise the Fast
Find paths changed here.
