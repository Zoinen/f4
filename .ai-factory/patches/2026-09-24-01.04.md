# File field controls lost in native scene projection

**Date:** 2026-09-24 01:04
**Files:** `internal/nativeui/scene.go`, `internal/nativeui/scene_incremental.go`, `internal/nativeui/model_test.go`, `internal/nativeui/incremental_test.go`
**Severity:** medium

## Problem

The Details columns popup opened with an empty list even though the Go panel model contained seven EXIF field descriptors. File-field filters and grouping changes also disappeared from incremental panel updates.

## Root Cause

The native UI adapter reconstructs typed `PanelModel` values from the legacy semantic map before sending them to Qt. That conversion copied the older gallery fields but omitted the newer file-field descriptors and related grouping/filter state. Separately, the bounded incremental state allowlist excluded group ranges and file-field state, so presentation changes could not reach the existing Qt reducer.

## Solution

Preserved file-field descriptors, filters, sort/group settings, pending counts, and group ranges in the typed panel projection. Added the corresponding presentation fields to incremental state updates. Regression tests cover both the full panel projection and the incremental update packet. A one-time VTUI debug message records that descriptors survive projection.

## Prevention

- When extending a semantic panel model, update every typed projection and serialization boundary, not only the source model and QML consumer.
- Test both initial scene snapshots and row-free incremental updates for new panel fields.
- Keep Go patch allowlists and Qt patch validators aligned.
