# Use interpolating cubic filtering for image magnification

**Date:** 2026-09-17 02:35
**Files:** third_party/ZoinGallery/resources/viewer_resample.frag, third_party/ZoinGallery/resources/viewer_resample.vert, third_party/ZoinGallery/tests/ViewerResampleGpuTest.cpp, third_party/ZoinGallery/CMakeLists.txt, third_party/ZoinGallery/README.md
**Severity:** medium

## Problem

Magnified images lost fine-line contrast because the magnification branch used
the texture sampler's bilinear interpolation. The existing custom convolution
was only applied to reduction.

## Root Cause

The shader returned a hardware-filtered sample whenever neither source axis
was minified. This also bypassed the transfer-function decoding used by the
reduction filter. Cubic weights alone would not fix this if neighboring encoded
texels were combined by hardware before decoding.

New 175% framebuffer regressions also exposed an existing placement error for
oversized, clipped images. A 400-pixel image axis projected to 398.9352 pixels
through a rounded framebuffer; snapping its projected center restored the
extent but placed its leading edge at -1 instead of 0. A large negative pan
could shift the sampled source by three rows.

## Solution

Magnification now uses a separable 4-by-4 Catmull-Rom kernel, with B=0 and C=0.5.
Each texel is decoded independently and filtered in premultiplied linear light.
The existing alpha/RGB bounds, transfer encoding and output dithering are shared
with reduction. Exact aligned identity sampling still returns first. Reduction
weights, image decoding and color-profile processing are unchanged.

For oversized axes at rest, recover the nominal physical origin before rounding
it to the framebuffer grid. This uses the viewer's existing unit/cardinal
ancestor-transform invariant. Smaller images retain center-based placement;
animation frames remain continuous.

Analytic quarter-phase stripe values were 64/191 before the change and are now
110/236, within one byte of the expected 110/237 after output dithering. An
independent CPU oracle uses cubic Hermite interpolation with finite-difference
tangents, rather than reproducing the shader's polynomial coefficients.

The numerical GPU suite covers fractional magnification, transparency and hidden
colors, single-row/column sources, actual 175% scene geometry, clipped edges,
large negative pan, and fractional motion followed by exact resting alignment.
The full GPU suite, related QML interaction and reusable-viewer tests, real-host
first-native-zoom and import checks, Windows dependency audit, embedded-host
materialization tests, and portable launcher build pass. No visual testing was
performed.

CTest now supplies the Basic controls style required by the static GPU fixture
and the 175% scale required by the reusable-viewer geometry tests, instead of
depending on the invoking shell's environment.

## Prevention

- Test magnification independently from reduction and aligned identity sampling.
- Use analytic contrast assertions plus an independently formulated CPU oracle.
- Decode each source texel before convolution; hardware interpolation of encoded
  values is not equivalent to filtering in linear light.
- Check actual output pixels as well as scene geometry at fractional DPR,
  including oversized images and large positive/negative pan limits.
- Declare required Qt style and scale in each CTest environment.
