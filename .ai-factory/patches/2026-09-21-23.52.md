# NetFox cached navigation selection lag

**Date:** 2026-09-21 23:52
**Files:** internal/panel/directory_cache.go, internal/panel/file_panel_test.go
**Severity:** medium

## Problem

When navigating back into a NetFox directory that already had a cached
listing, the cached rows appeared immediately but the cursor stayed on the
previous row until the fresh remote `ReadDir` completed. This made returning
from a child directory feel delayed and could leave the wrong item selected
during the refresh.

## Root Cause

`ReadDirectory` restored the cached catalog before starting the authoritative
remote refresh, but `PendingSelection` was only consumed by the final
`ReadDir` completion path. The cache restore rebuilt the rows without applying
that pending name, so the visible catalog and the intended navigation
selection were temporarily out of sync.

## Solution

After restoring a cached catalog, apply a matching `PendingSelection` by entry
name immediately and leave the pending name intact for the authoritative
completion to validate again. The fresh listing therefore keeps name-based
selection correctness if ordering or contents change, while the cached view
already paints the correct cursor. A `[FIX:directory-cache]` diagnostic records
the immediate cached selection.

The regression test blocks the remote refresh after the cache has been shown
and verifies the cursor target both before and after the refresh is released.

## Prevention

- Cached navigation snapshots must apply pending path-entry selection before
  starting or completing a remote refresh.
- Keep the pending target by stable name until authoritative content confirms
  it; never carry a stale numeric cursor index across a refresh.
- Test intermediate loading states, not only the final post-refresh state.
