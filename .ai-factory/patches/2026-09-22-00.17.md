# Held Enter is queued and replayed against the cached cursor

**Date:** 2026-09-22 00:17
**Files:** qt/host/src/F4GalleryBridgeIntents.cpp, qt/host/src/F4GalleryBridgePanelSync.cpp, qt/host/tests/F4GalleryBridgeTests.cpp
**Severity:** medium

## Problem

When Enter was held on a cached directory, the source and destination
catalogs could both be available immediately, but native key autorepeat could
arrive while the destination still had its provisional/default cursor. The
destination initially selected `..`, so applying a repeat before the cached
selection was restored could navigate back to the parent or keep walking
through directories.

## Root Cause

The bridge had only a transient view of the directory transition: the first
destination scene could acknowledge the path before the cache had applied the
remembered cursor. Repeated events then had no safe stable row identity to
use, and a repeat could be interpreted against `..`.

## Solution

Directory transitions now retain every repeat as a semantic count instead of
discarding it. The bridge records the expected destination cursor: `..` when
entering a directory and the basename of the directory just left when
opening its parent. It acknowledges the path immediately, but waits to replay
the queued event until that stable cursor is present in the cached catalog. It
then resolves the current stable entry ID and dispatches one queued open,
carrying any remaining count through the next transition. No autorepeat is
ignored merely because an open is in flight or because a cached catalog is
still being applied. `[FIX:cached-enter]` logs record queueing, cursor waits,
and replay.

The regression tests model both directory-entry and parent-entry navigation.
They verify that an initial `..` cursor is not used prematurely and that three
queued repeats produce three subsequent stable-ID opens across the resulting
path transitions. Existing repeat-reconciliation tests remain covered.
