# Preserve dense catalog promotion when a delta is supplied

**Date:** 2026-09-12 12:41
**Severity:** medium
**Files:** third_party/ZoinGallery/src/embed/GallerySession.cpp, third_party/ZoinGallery/tests/MasonryLayoutModesTest.cpp

## Problem

iPhone /DCIM/100APPLE remained a uniform grid with distorted masonry thumbnails
even after real image dimensions arrived. IMG_0007.JPG was correctly read as
540572 bytes and decoded with original dimensions 1170x2532.

## Root Cause

GallerySession chose sparse reconciliation if either the incoming catalog or
the previous model was sparse. A completed dense catalog carrying an identity
delta therefore retained sparse mode. The sparse layout intentionally uses
uniform placeholder geometry and cannot apply the normal masonry dimensions.

## Solution

Use sparse reconciliation only when the incoming catalog is still deferred.
Promote completed catalogs through the existing dense reset transaction, which
notifies the layout and retains compatible source state. Opt-in media timing
records [FIX:masonry-dense-promotion] with row count and delta presence.

## Prevention

The regression reproduces a 48-to-136-row transition carrying an identity delta.
Before the fix it fails because the completed model remains sparse. Afterwards
portrait and landscape metadata produce their respective natural masonry
geometry. Run at DPR 1.75 alongside sparse 30K-row bounded-rendering and
finalization tests. Further coverage should exercise promotion while a viewer
request is pending and repeated sort changes at the paging threshold.
