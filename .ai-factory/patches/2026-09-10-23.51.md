# Export custom Settings decorations and viewport semantics

**Date:** 2026-09-10 23:51
**Files:** internal/settings/center_semantic.go, internal/settings/center.go,
internal/nativeui/scene.go, sdk/extui/model.go,

**Severity:** medium

## Problem

Settings showed editors and checkboxes in Qt but omitted Search, category and
field captions, group frames, and help text. Scrolled page content could intrude
into fixed dialog regions.

## Root Cause

The custom Settings widgets paint decorations directly in Show. Inheriting the
Window/Group semantic providers exported only registered interactive children.
A group carrying a viewport also lacked an explicit scroll/clipping contract.
Adding viewport nesting exposed a pixel correction dependency that only watched
a fixed-depth list of ancestor positions, not shared translation corrections.

## Solution

The settings package now publishes decorations from the original descriptors,
groups existing exported controls without changing their Go owners, and exposes
full unscrolled content with row scroll metadata. The typed projection preserves
these fields. Dialog and viewport rendering share row metrics, and Qt independently
clips/scrolls the page and help. Group title backgrounds and shared scroll
translations snap to physical pixels; leaf corrections observe ancestor correction
changes through the full hierarchy. The final packaged-launch check also caught
new QML files omitted from the production host manifest despite passing fixture
tests. Production and shell tests now use one shared QML resource manifest in
`qt/host/cmake/F4HostQmlFiles.cmake`, including resource aliases.

## Prevention

- A custom console painter must supply matching semantics for passive content.
- Test both owner export and typed wire projection, including action/focus routing.
- Keep source text separate from terminal wrapping and mnemonic presentation.
- Exercise nested viewport text and icons after fractional scrolling at DPR 1.75.
  The regression first measured a group title at 77.5 physical pixels and its
  title background at 316.25 physical pixels; wrapper-only checks missed this.
- Capture both the top and scrolled page and inspect the smaller captions.
- Keep test and production resource manifests identical and verify the freshly
  embedded host actually creates a window before replacing a working build.
