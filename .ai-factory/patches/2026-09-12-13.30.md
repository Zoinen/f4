# Commit external masonry metadata by visual row

## Problem

The lightweight external-catalog path bypassed the historical row accumulator.
It applied every arriving dimension immediately, coalescing only the rewrap
timer for 16 ms. iPhone metadata arriving independently therefore moved geometry
while a row was still incomplete.

## Root Cause

Submission-order isLast is not a completion barrier. The presentation facade
also exposes a fixed role set, so a completion role added only to the source
model cannot reach the layout.

## Solution

Retain pending dimensions in the existing brick modelKnownSize field and keep
originalSize as the committed geometry. Use the existing layout strategy to
calculate future rows, requiring resolved metadata through one lookahead entry
that decides the wrap. Commit complete rows independently on the coalesced timer.
Live iPhone testing exposed why current placeholder-row boundaries were not
enough: portrait dimensions repeatedly pulled another unknown file into a
previously committed row. The extended regression reproduced this before the
candidate-row fix. Cache batches retain their atomic fast
path. Carry optional metadataSettled through the facade; invalid metadata and
exhausted transport retries settle with placeholders, while source invalidation
clears completion state. No second size cache or global catalog barrier is used.
Opt-in tracing records [FIX:masonry-row-metadata] row commits.

## Prevention

The regression first observed geometry changing from 157x163 to 87.5483x186.151
after a single completion. Exercise the real facade, out-of-order completions,
misleading isLast, an independently ready last row, and invalid metadata.
Keep cache-batch, catalog promotion, reorder, reentry and DPR 1.75 checks.
The native label regression measured a physical Y origin of 246.75 after a
metadata commit. Snap the label surface extents and padding, then use the shared
scene-space correction so the actual Text leaf retains an integral origin and
unit transform, even with fractional ancestor positions.
Further coverage should combine resize and source replacement during a partially
resolved row, and device disconnect/reconnect while retrying metadata.

## Visual slow-motion diagnostic

`F4_GALLERY_ROW_DELAY_MS=1000` deliberately paces ready-row commits, including
cached metadata and reentry. Use precise nonblocking timers, one row per tick,
and the existing reset generation to discard stale callbacks. Unset the variable
for production behavior. The diagnostic test covers pacing, cached completion
and replay; it is an opt-in observation aid, not a change to normal batching.
