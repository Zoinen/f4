# Directory size caching in the active Qt v4 worktree

**Date:** 2026-11-06 13:40 Europe/Moscow
**Files:** internal/panel/list_size.go, list.go, autofilter.go, qt_semantic.go and tests; internal/app/actions.go and tests; vfs/scanner.go and tests; qt/host/tests/F4GalleryBridgeTests.cpp; docs/FILE_FIELDS.md
**Severity:** medium

## Problem

Changes made in the older main checkout did not reach the Qt development
launcher. That checkout sends ExtUI v2 while the launcher's Qt host expects v4.
Switching to another backend did not satisfy the requested Qt behavior.

## Root Cause

`run-f4.command` identifies the active Qt worktree explicitly. The main checkout
is an older source tree and lacks the current native/paged metadata architecture.
Its simple entry formatter cannot update the actual v4 Qt metadata path.

## Solution

Apply the feature in the active `qt-run-current` worktree, which already owns
the complete ExtUI v4 implementation. Build its own Go binary and matching Qt
host rather than weakening version checks or pretending v2 messages are v4.

Remember completed subtree totals in the existing scan, preserving both payload
and directory-entry bytes. Restore hints once during each ingestion path,
including previews, bounded windows, worker presorting/pending-source publication,
cached listings and synchronous loads. Preserve measured directory sizes when
phased VFS metadata arrives.

Format authoritative GUI row sizes within 11 characters. Include approximation
state in metadata fingerprints and immutable snapshots. Fresh single/multi-folder
F3 clears it and commits the normal metadata revision.

The cached Qt build referenced the removed macOS 27.0 SDK. Reconfigure that build
against the installed 27.2 SDK, keeping deployment target macOS 13.0, then rebuild
the host and Qt tests. No global SDK settings or protocol downgrade is required.

## Prevention

Resolve the launch script and active worktree before selecting build sources.
Test the full producer-to-frontend metadata path, including an approximate-to-exact
transition with identical bytes and an unchanged catalog. Protect computed fields
from later raw filesystem enrichment. New regression tests cover full, deferred
and paged exports, cancellation, navigation, VFS isolation, phased enrichment,
fresh F3 and Qt Gallery's preservation of authoritative K/M/G strings.

## Verification

- The new Qt size-column test failed before implementation and now passes.
- Full Go panel, app, nativeui, plughost and extui suites pass.
- VFS scanner/cache regressions pass. The full VFS suite still reports the
  unrelated `TestEveryElevatedCallChecksTheOperation` auditor failure for
  `os_vfs.go`'s existing `readDirPhased` elevation call. Remaining VFS tests pass
  when that auditor is excluded.
- The rebuilt Qt host passes `ExtUiProtocolTest` and the new
  `deferredDirectorySizesPreserveAuthoritativeText` regression, together with
  `deferredMetadataIsFrameGatedRevisionedAndChunked`.
- Full Gallery bridge tests crash in the existing `viewerOwnsEscapeAndZoom`
  case. Running the original test list without the new directory-size test
  reproduces the same crash.
- The worktree's freshly built Go binary and Qt host are running together.
  The visible Qt window shows the measured `ISSUES` directory as `174 489`;
  the live scan log confirms successful F3 results and no handshake rejection.
