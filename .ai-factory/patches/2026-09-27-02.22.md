# Follow settled breadcrumb geometry before the first frame

**Date:** 2026-09-27 02:22
**Files:** `third_party/ZoinGallery/qml/PathControl.qml`, `qt/host/tests/F4QuickViewSurfaceTests.cpp`
**Severity:** medium

## Problem

Navigation between overflowing paths briefly displayed the previous scroll
position and could leave the current directory outside the visible region.

## Root Cause

The path control used `Qt.callLater` to assign its end offset once. The Row's
content width is resolved during polish, so deferred JavaScript was neither a
first-frame barrier nor a guarantee that the final width was available.

## Solution

Reinstall a reactive end-offset binding synchronously on path/width changes.
It follows Row geometry through polish. Release the binding on hover entry and
wheel input, preserving in-layout expansion and manual ancestor scrolling.
Include contentX in leaf pixel-alignment dependencies and apply the existing
scene-space correction to the root slash. Optional `debugPathLayout` logging
reports reset inputs with `[FIX:breadcrumb-scroll]` without path contents.

## Verification

The first-frame regression failed before the fix in compact and full-name
modes: contentX remained zero rather than 389.429/653.429 logical pixels.
Afterward, six alternating parent/child transitions per mode start at the end
and their first-frame path captures equal the settled captures byte-for-byte.
The same test checks text, slash and separator physical origins and unit
transforms at DPR 1.75. It exposed and covers the root slash's fractional y.
All 14 focused cases passed, including hover animation, wheel input, stable
text placement, URI navigation and device root labels.

## Prevention

Test the first rendered frame, not just eventual geometry after a wait. Keep
automatic geometry following separate from intentional user scroll/hover.
Include manual scrolling before navigation and both compact/full-name modes.
