# Detach retained layouts when their preview model is destroyed

**Date:** 2026-09-16
**Files:** third_party/ZoinGallery/MasonryLayoutProperties.cpp, MasonryLayoutModelReset.cpp, tests/MasonryLayoutModesTest.cpp
**Severity:** high

## Problem

Repeated entry and exit from P:\[Year 2026] crashed the Qt host with access
violation 0xc0000005. Reproduced in the running application under CDB within
several navigation cycles.

## Root Cause

A pooled folder delegate retained a MasonryLayout after its preview catalog
was deleted. The layout stored a raw model pointer without handling destroyed.
A queued lightweight rewrap called materializeImageForIndex, which dispatched
rowCount through the destroyed model's vtable. The failing address resolved
to QObjectPrivate::writeToDebugStream instead of the model method.

Model-only lifecycle tests and even repeated fast QML navigation with a small
fixture did not reproduce the allocator/timer interleaving seen with the real
photo collection. A deterministic ownership regression confirmed model() still
returned the deleted object's address.

## Solution

Handle QObject::destroyed synchronously: clear the model pointer and role cache,
reset the layout, invalidate scheduled rewrap/delegate generations, and release
visual facades. Do not query or cast the destroyed model. Do not retain reset
slots when there is no model: their ImageFile objects are already destroyed.

## Prevention

Test deletion independently of navigation timing. Also exercise 20 displayed
folder-to-folder navigation cycles, requiring usable images after each reentry
and no retained leases at the end. Both tests pass. The full Masonry modes and
DPR 175% suites pass, as do static QML/import and embedded payload checks.
The corrected real application survived 30 navigation cycles and remained
responsive. CDB stack and regression logs are in .diagnostics/folder-*.
