# Help shares ordinary dialog chrome and exposes link hover

**Date:** 2026-09-12 01:03
**Files:** qt/host/qml/GenericDialog.qml, qt/host/qml/DialogOverlay.qml, qt/host/qml/HelpContent.qml, qt/host/qml/OverlayHost.qml, qt/host/tests/F4OperationsQueueTests.cpp
**Severity:** medium

## Problem

F1 used a separate hand-built window header and had no visual feedback when
hovering links. Its title/close/back controls differed from ordinary dialogs.

## Root Cause

The initial help fix treated its content and chrome as one new overlay instead
of extending the existing dialog. It supplied clickable rich-text links but
only used hoveredLink to choose a cursor, not to style the hovered link.

## Solution

GenericDialog owns an optional content component and an optional owner-routed
Back action. HelpContent renders only formatted rows and its scrollbar inside
the normal DialogOverlay/GenericDialog path. There is no help-specific chrome.
The shared title/header and geometry are pixel aligned; the Back button reuses
F4Button and the shared semantic icon resolver. Link hover changes colors only,
without changing owner selection, text layout, or sending a Go action.
Existing F4_HELP_TRACE diagnostics continue to cover navigation/viewport actions.
The physical-pixel regression also caught a 26.25-by-26.25-pixel Back icon at
DPR 1.75: RowLayout replaced the snapped image size with its intrinsic size.
F4Button now supplies snapped preferred icon dimensions to the layout.

## Prevention

The regression first failed to find the common semanticDialog-help surface.
Coverage checks common title, Back and Close leaves at DPR 1.75, hover/leave,
click routing, ordinary-dialog Back visibility/action changes, scrolling and
rendered captures. Re-run ordinary-dialog move/resize/focus and Settings tests
when changing this shared chrome. Additional coverage could exercise long
translated titles with the optional Back button at minimal dialog width.
