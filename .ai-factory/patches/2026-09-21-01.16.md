# NetFox root breadcrumb keeps the canonical URI hidden

## Problem

The first breadcrumb in a NetFox panel could display `net://` instead of the
user-facing `Network` label. The panel still needed to navigate using the
canonical `net://` URI.

## Root Cause

The QML path control renders the first URI segment from its display text unless
the host supplies an explicit `rootBreadcrumbLabel`. `FilePanelChrome.qml`
handled the Android, iOS, and AI URI prefixes but omitted `net://`.

## Solution

Added the `net://` mapping to `Network` in `FilePanelChrome.qml` while leaving
`navigationPath` unchanged. Added a fractional-DPR regression row that uses
`title = net://` so the test exercises the QML fallback path directly.

## Prevention

The regression test is `deviceBreadcrumbLabelsPreserveCanonicalNavigationAt175Percent(netfox-manager)` in `F4QuickViewSurfaceTests`. It verifies the displayed root label, canonical navigation path, root click behavior, and physical-pixel alignment.

## Verification

- The regression test failed before the QML mapping: actual `net://`, expected `Network`.
- The targeted regression test passed after the mapping.
- The complete parameterized breadcrumb test passed: 9 passed, 0 failed.
