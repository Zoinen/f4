# Image-dependent text alignment in enlarged gallery rows

**Date:** 2026-09-22 23:16
**Files:** `third_party/ZoinGallery/qml/GalleryEntryDelegateBase.qml`, `third_party/ZoinGallery/qml/GalleryThumbnailCompactLayer.qml`, `third_party/ZoinGallery/tests/GalleryQmlInteractionTest.cpp`
**Severity:** medium

## Problem

At high zoom in Details and two/three-column views, a filename beside a portrait thumbnail started much farther left than a filename beside an icon or a missing thumbnail. The mismatch became more noticeable as rows grew.

## Root Cause

The previous spacing fix narrowed the entire preview slot according to image aspect ratio. Both text layouts anchor their filename after that slot, so image metadata inadvertently determined the text column's x-position.

## Solution

Restored one square preview slot width for every row. A portrait thumbnail now occupies an aspect-ratio-sized region at the **right edge inside** that slot; the text anchor remains independent of image type or thumbnail availability. A DPR 1.75 regression check first measured a 106-logical-pixel mismatch, then measured identical text x-positions in Details and both column modes. The existing visible-thumbnail gap and multiline-name checks still pass; the complete GalleryQmlInteractionTest passes, and the rebuilt host was inspected live.

## Prevention

Treat row slot geometry as a shared alignment contract, separate from how media is painted inside the slot. For any presentation change, compare filename origins across image, icon, and no-preview rows at both compact and enlarged densities. Further useful coverage is a runtime toggle of thumbnail visibility in the same row.
