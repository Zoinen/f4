returns immediately for nonfatal messages. On the first Qt fatal message,
with an explicit destination, it writes a bounded JSON record: message and

This hook covers Qt fatal messages, not every possible direct abort or

## Validation corrections and retained limitations

B1's original capture wrapper returns 1 after producing its complete packet:
it incorrectly assumes D3D12 means zero process-wide D3D11 device records.
The D3D11 probes accept native `ID3D11DeviceContext` objects and show three
auxiliary owner threads, all distinct from the main D3D12 render thread.
Revalidation permits those bounded records while retaining zero first maps,
zero eligible uniform use, and all error/overflow checks. Their precise
subsystem origin is not inferred from owner IDs alone.

Two other inherited assumptions are corrected: generic buffer-unmap stage
records can exist on D3D12 and must be retained/capacity checked; the D3D12
dependency fallback builds zero entries, consistent with the earlier checks.
No pixel, frame-time, motion or coverage threshold changes. B1's original
return code and explicit revalidation receipt remain. B2 runs with corrected
checks and returns 0; its strict performance analysis still fails.

No fatal record or early-exit record is generated by either repeat. Both
owned diagnostic process trees are stopped after completion. The existing
normal Go/Qt processes remain alive. Full raw packets are preserved with
SHA-256 verification and transparent compression; only verified duplicates
are retired. The exact raw locations, source snapshots and compact results
are indexed alongside this report.

The next optimization must address the remaining end-to-end presentation
stalls and motion error on the normal renderer; switching backends alone
does not meet the target. The fatal-only probe remains available if the
